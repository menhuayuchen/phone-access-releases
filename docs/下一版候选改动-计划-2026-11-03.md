### B1 参考方向（2026-11-03 用户建议）

用户建议参考 **Sunshine（被控端）+ Moonlight（客户端）** 这套开源方案：我们的目标是在它们基础上
做得**更容易配置**。可按这个思路做 B1 的第一轮技术调研（不动代码）：
- Sunshine 的采集/编码链路：DXGI Desktop Duplication 抓屏 + 硬件编码（NVENC / AMF / QSV / 软件 x264），
  低延迟推流；Moonlight 客户端协议（GameStream/RTSP 私有协议，UDP 端口 47984-48010）。
- 我们不能直接用它俩的协议：手机端是**浏览器**，没有原生 Moonlight 客户端。
  但可以借它们的「采集 + 硬编」部分，输出 H.264 走 WebSocket/HTTP，手机用 **WebCodecs VideoDecoder**
  解码（Chrome/Edge Android、Safari 16.4+ 支持）→ canvas 渲染；这比 MJPEG 省流量、可能上 60fps。
- 第一步仍是**测量**：确认现在 2560 档 24–30fps 的瓶颈在抓屏读回、JPEG 编码还是传输/解码；
  再决定是「GDI 抓屏 + turbojpeg 提速」还是「DXGI + 硬编 + WebCodecs」大改。
- 差异化保持：免装 App、Tailscale 直连、配置简单（不能像 Sunshine 那样要手动配编码器/端口）。
