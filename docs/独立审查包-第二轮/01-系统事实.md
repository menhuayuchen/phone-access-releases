## 一、产品是什么、边界在哪

```
客户的手机 ──Tailscale 私有网络──> 客户的电脑（本产品）
```

- **没有中心服务器**：产品运行时不向任何外部地址发请求（已实测：源码里除 `127.0.0.1`/`localhost` 外无任何域名）
- **不走公网**：服务只绑回环 + 私有网段 + Tailscale 的 `100.64.0.0/10`
- **不预置凭据**：安装包里没有卖家的任何账号、密钥、回连地址
- **卖家进不去客户电脑**：客户用**自己的** Tailscale 账号登录，卖家不是那个 tailnet 的成员

## 二、进程与端口

| 进程 | 端口 | 是否所有客户都有 |
|---|---|---|
| `screen-server.mjs` | 8660（127.0.0.1 + tailnet IP + 局域网 IP） | 有 |
| `capture.exe` | 无网络 | 有 |
| `input.exe` | 本机命名管道 | 有 |
| `audio.exe` | 本机命名管道 | 有 |
| `supervise.ps1` | 无网络（每 8 秒探 `/health` 保活） | 有 |
| `tunnel-proxy.mjs` × 3 | 8642 / 8650 | **仅 `enableDsh=true`（卖家自用）** |
| `dsh web` | 127.0.0.1:8642 | **仅 `enableDsh=true`** |

**客户版 `product.config.json` 里 `enableDsh = false`**，所以 8642/8650 这两套完全不启动，客户机上看不到任何 DSH 痕迹。

## 三、鉴权（三层，上一轮 H1 的修复点）

**背景（上一轮的 H1）**：`tailscale serve` 把 `https://<机器名>.ts.net/` 转发到 `127.0.0.1:8660`，
于是**远端请求在服务端看起来是 `remoteAddress = 127.0.0.1`**。原来的"本机连接免密钥"逻辑因此被穿透，
未授权可以盲操作鼠标键盘。

修复后分三层：

| 层 | 路径 | 规则 |
|---|---|---|
| A 普通 | `/health` `/licence` `/manifest.json` `/sw.js` `/icon-*` `/branding/*` | `isLocalConn` 可免密钥。`/health` 必须保留豁免，因为 `supervise.ps1` 每 8 秒无密钥探活，去掉会导致重启风暴 |
| B 严格 | `/input` `/mode` `/unblock` `/showdesktop` `/rtc-*` `/sources` `/cursor` | **始终**要密钥 + 同源 |
| C 始终 | `/` `/frame.jpg` `/stream` | 始终要密钥 |
| 特殊 | `/exec` | 要密钥 + `Content-Type: application/json`（防 CSRF） |

`/health` 返回的 `fg=`（前台窗口标题）和 `input.foreground` **只给带密钥的请求**。

**已知弱点（请看 `03-已知问题.md`）**：非浏览器客户端可以伪造 `Host` 绕过同源检查，
但因为仍然需要密钥，风险有限。

## 四、许可证

```
客户机器 ──> 机器码（硬件指纹，形如 5FE5-CFE7-7B27-370B）
                │
                ├─ 客户把机器码发给卖家
                ├─ 卖家用自己的私钥离线签一个 licence.json
                └─ 客户把短码粘进手机页面的输入框（或把文件丢进安装目录）
```

- **签名算法**：RSA-2048 / SHA-256，签名原文是固定字段用 LF 拼接：`name\nmachine\nissued\nexpires\nedition\nver`
- **公钥内嵌在 `screen-server.mjs` 里**（JWK 形式），私钥只在卖家机器上，**永不进包**
- **验证在 Node 侧**（`checkLicenceObject`），不是只看 PowerShell 生成的状态文件
- `licence.state.json` 只是给页面显示用的（机器码/联系方式/品牌），**不作为放行依据**
- **软停**：没有服务器，所以无法远程吊销。许可证到期后画面服务返回 402，但装过的程序还在

**已知弱点**：`machine.id` 文件可写，所以"许可证 + 伪造的机器码"能被搬到别的机器上。
设计目标是"防随手转发"，不是"防逆向"，这一点是接受的取舍。

## 五、画面管线（理解帧率/延迟必读）

```
capture.exe (C#, GDI BitBlt)  ──JPEG 帧──> screen-server  ──multipart──> 手机 <img>
        │                                                   │
        │                                                   └─ 可按请求宽度二次缩放 (/stream?w=)
        └─ 同时被 decode.mjs 读 ──> 解码成 I420 ──> VP8 编码 ──> WebRTC 给手机 <video>
```

- **抓屏是纯 CPU 活**：`BitBlt` 整屏 + JPEG 编码。2560×1600 = 410 万像素，实测 **18–24 fps 就是天花板**（CPU 决定）
- **抓屏宽度是启动参数**：`start-screen.ps1` 调 `Get-CaptureGeometry` 算出 `宽x高`，传给 `capture.exe` 和 `screen-server.mjs`
- **`capture.mode` 文件**：`screen-server` 每 700ms 写一次（`mode/monitor/window/width`），`capture.exe` 读它来切换抓取目标
- **帧间隔上限**：`CAP_LEVELS = [33,45,60,80,110]` 毫秒，写在 `capture.interval` 文件里；拥塞时逐级降速
- **WebRTC 路径**：`RTC_W = 抓屏宽 / 2`（当前配置 `rtcWidth=0`），码率固定 3000 kbps、帧率 24

**手机流量实测**（单帧 `q80`）：
`2560→322KB` `1920→257KB` `1440→153KB`；按 24fps 换算清晰模式约 **26 GB/小时**，
WebRTC「流畅」约 **1.3 GB/小时**。所以文档里明确写了「用手机流量请点流畅」。

## 六、模式按钮的真实语义

| 按钮 | 传输 | 抓屏宽 | 帧率 |
|---|---|---|---|
| 清晰 | MJPEG 流 | 抓屏原宽 | 抓屏能到多少就多少 |
| 流畅 | WebRTC | 抓屏宽的一半 | 配置 24，CPU 受限实测约 12–15 |
| 省流量 | 轮询 `/frame.jpg?w=&q=45` | ≤1280 | 5 帧/秒（`LOWBW_MS=200`） |

**注意**：顶栏的「清晰/流畅」改的是**送流宽度**，不是抓屏宽度。
抓屏宽度由 `product.config.json` 的 `screen.maxCaptureWidth` 决定，改了必须**完整重启**才生效。

## 七、安装做了什么（`install.ps1`）

1. 提权（整个安装只弹一次 UAC）
2. 环境体检（Windows 版本、域加入、空间、.NET、Tailscale 连通性、端口）
3. 复制 355 个文件到 `%LOCALAPPDATA%\PhoneAccess`（`robocopy /IS`，事后**验内容哈希**而不只是文件在不在）
4. 写配置（**已存在的 `product.config.json` 保留，只补缺失字段**）
5. 防火墙规则（**只放行 `100.64.0.0/10`（tailnet）**，并**显式拒绝**三块 RFC1918：10/8、172.16/12、192.168/16）
6. Defender 排除项（**只排除具体可执行文件**：capture.exe / capture.exe.bak / input.exe / audio.exe / sources.exe / runtime\node.exe，外加高权限注入器那份 input.exe。第二轮 P0-2 之前是排除整个安装目录，已收窄）
7. 计划任务（开机自启 + 高权限注入器）
8. 桌面文件夹（启动/重启/自查/停止/手机入口/卸载 + 使用说明.md + 报告/ + 二维码/）

## 八、明确不做的

- 不做遥测、不收集使用数据
- 不做自动静默更新（只有客户点「检查更新」才联网一次）
- 不给卖家留远程入口（技术上到不了）
- 不加默认口令、不加客户端自动提权
