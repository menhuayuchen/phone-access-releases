## 二、规则（必须遵守）

1. **发版规则**：每出一个大版本，必须**自用版 + 发布版两套**都打；**任何发布都必须先得到用户明确同意**（改 version、传 Gitee/GitHub、打 tag、改站点下载都算发布）。
2. **`.ps1` 必须 UTF-8 with BOM**；编辑后必须 `[Parser]::ParseFile` 检查 + 实际跑一次。
3. **永远不要往 .ps1 里写 JS 风格的 `//` 注释**——PowerShell 会把它当命令，运行时报 CommandNotFound，而且**语法检查发现不了**（本会话踩了两次）。
4. 改 `page.mjs` 里内联脚本后，必须：从**线上页面**抽出 `<script>` → `node --check`；再到浏览器确认 `window.__paExp` 存在（脚本完整跑完的判据）。本会话出过 `IS_DESKTOP` TDZ，症状是"一直转圈：正在连接画面"。
5. **不要用 PowerShell 控制台判断中文文案**（会显示成乱码，造成误判）；用 `node` 读文件 + `split` 计数，或 `Select-String -Encoding UTF8` 对文件查。
6. 重启服务用 `POST /restart-service`（只退出进程）。**不要用 `/offline/on` 重启**——它会把 `screen.offline` 写成 true，用户多次发现"离线模式自己开了"。
7. **Sunshine 配置不要只靠 API POST**（不会持久化，会被重写成只剩几行）。改 `C:\Program Files\Sunshine\config\sunshine.conf` 要提权，改前备份，改完重启 `SunshineService`；重启脚本要 try/finally 保证服务最终是 Running（本会话出过一次服务停着没起来 + conf 被写空）。
8. 用户明确说过：**画质与流量正文不要改**；文案要"说人话"，但技术细节放进折叠区。
9. 任何涉及"地址/状态显示"的改动，**先用接口实测返回值**，再确认页面渲染，不要只看代码。
10. 不要留半成品开关在生产配置里：`screen.lan` 目前默认 false，请求级仍被安全过滤拦（见待办）。

## 四、待办 / 已知问题（新会话从这里开始）

1. **两个光标重叠是否真的解决**：`56cf74b8` 已做互斥并实测（body=ext-mouse、#mcur=#dot=none、只留 expCursor），但**用户手机未复验**。若仍重叠，先看 `window.__paLastPtr` 的值，再查该设备是否上报 `mouse`。
2. **"外接鼠标变触屏"** 的根因若不在 pointerType，下一步查：该设备 pointermove 是否被浏览器合并/节流、`state.control` 是否 off、`setPointerCapture` 是否让后续 move 落到别处。
3. **局域网直连没做完**：`screen.lan=true` 能绑 LAN + 防火墙放行，但请求仍被 `sourceAllowed/授权` 拦（连接建立即被 destroy）。要么定位那一层，要么明确放弃（官方通道只走 tailnet）。
4. **音频 EPERM**：`screen-server.log` 每秒刷 `audio: [audio] disconnected (EPERM)`；画面正常但**声音可能没通**，需要查 audio.exe 管道 ACL（注入器管道已显式给 Everyone 访问，音频同理）。
5. **真光标形状覆盖**：位图按形状缓存；若某状态（手型/I 形）仍是旧 SVG，查该形状的 img 是否发过（`window.__paCurImgs`）。
6. **1.0.18 尚未发布**，等用户明确同意后再发 Gitee + GitHub 并更新站点下载区。
