# 独立审查包 · 从这里开始

## 这是什么

一个**商用软件产品**的源代码，准备交付给付费客户。需要一次**独立的安全与健壮性审查**。

产品形态：在 Windows 电脑上安装一个服务，让用户通过手机浏览器远程查看和操作这台电脑（类似向日葵 / ToDesk 的自建版），带离线许可证校验。

**目标客户**：内容创作者（非技术人员）。卖家提供远程安装和售后支持。

---

## ⚠️ 三条规则，请先读

### 1. 不要相信代码注释里的论证

这份代码的注释是**原作者**写的，包含大量"为什么这样做是对的"的论证。**把每一条论证当成待验证的主张，而不是事实。** 原作者可能已经自欺。

### 2. 不要相信"已验证"的标注

代码和文档里出现"实测"、"已验证"、"修复了"之类的词，都是原作者自己做的验证。**没有经过独立复现的验证不算验证。**

### 3. 不要被引导去看"看起来最危险的地方"

审查清单里列了问题，但清单本身是原作者写的——**作者的盲区不会出现在自己的清单里**。请自己通读，发现清单之外的问题同样重要，甚至更重要。

## 交付内容

```
00-从这里开始.md     ← 本文件
01-系统事实.md       ← 架构、信任边界、入口清单（纯事实，无判断）
02-审查问题.md       ← 分文件、带行号的具体问题
src/
  screen-server.mjs  ← 手机侧 HTTP 服务（鉴权、许可证、画面、输入、命令执行）
  page.mjs           ← 手机页面（触摸手势、键盘通道、许可证界面）
  licence.ps1        ← 许可证校验（机器码、RSA 验签、有效期）
  install.ps1        ← 安装器（复制、防火墙、计划任务、桌面图标、提权）
```

代码是**原样复制**，行号与 `02-审查问题.md` 里的引用一致。

## 建议的输出格式

按严重程度分三档，每条给出：

| 字段 | 说明 |
|---|---|
| 严重程度 | 高危 / 中危 / 低危 |
| 位置 | 文件名:行号 |
| 问题 | 一句话说清是什么 |
| 触发条件 | 攻击者/用户需要做什么才能触发 |
| 后果 | 最坏情况是什么 |
| 建议修法 | 怎么改（不用写完整代码） |

**如果某个问题你不确定，也请写出来并标注"不确定"。** 不确定的线索比遗漏有价值。

---

## 审查范围之外（不用看）

- 画面编解码的实现细节（`capture.cs` / `decode.mjs` / `rtc.mjs`）
- 音频转发（`audio.mjs`）
- Node 运行时与第三方依赖本身的漏洞（`node_modules/`）
- Tailscale 这个第三方服务本身

**重点在**：鉴权、许可证、信任边界、文件系统、提权、打包泄漏、边缘输入。
