## A. `screen-server.mjs` — 鉴权

### A1 · 679-681 行：本地连接判定

```js
const ra = String(req.socket.remoteAddress || '').replace(/^::ffff:/, '');
const la = String(req.socket.localAddress || '').replace(/^::ffff:/, '');
const isLocalConn = ra === '127.0.0.1' || ra === '::1' || (ra && ra === la);
```

**问题：**

1. `ra === la` 这个分支在什么网络条件下会成立？列出所有能成立的情形。
2. 有没有办法让一个**远程**连接呈现出 `ra === la`？
3. IPv6、NAT、反向代理、Tailscale 的转发，分别会怎样影响这两个值？
4. 如果这个判定被误判为真，后果是什么？（看 681 行之后的鉴权闸门）

### A2 · 506-516 行：`authorized()`

```js
function authorized(req, url) {
  if (url.searchParams.get('k') === KEY) return true;
  const cookie = req.headers.cookie || '';
  return cookie.split(';').some((c) => c.trim() === `screen-key=${KEY}`);
}
```

**问题：**

1. `KEY` 从哪里来、什么时候读一次？（看 196 行）
2. 密钥轮换后，这个比较还能通过吗？服务需要重启吗？
3. Cookie 的比较方式有没有问题？（完整 token 比对的时机、时序攻击是否可行）
4. 如果 `KEY` 是空字符串或 `undefined`，会发生什么？有没有代码路径能让它变成空值？

### A3 · 531-560 行：`rejectAuth()` 与失败计数

**问题：**

1. `noteAuthFail` 的计数表 `authFails` 会不会无限增长（内存耗尽）？
2. 锁定的粒度是 IP。如果一个 NAT 后面有多个用户，会发生什么？

4. 429 锁定状态会不会被用来做拒绝服务？

### B2 · 724-780 行：`POST /licence`（粘贴安装）

> 订正（原作者写错了）：这个接口**是需要密钥的**——鉴权闸门在它之前，只有来自本机回环的请求可以免密钥。

**问题：**

1. 这个接口**不需要许可证**就能调用。考虑一个已持有密钥、但尚未授权的使用方：
   - 请求体上限是 64 KB。超限时 `req.destroy()`。这之后的清理路径完整吗？
   - `JSON.parse` 失败时会走 `text = body`。这条路径有没有隐患？
   - base64 解码对超长输入的表现如何？
2. 验签通过后的写文件操作：
   - 目标路径是完全由服务端决定的吗？有没有任何用户输入进入路径？
   - 写入前有没有检查目标是否已存在？
   - 如果目标路径是一个符号链接，会发生什么？（考虑攻击者先在 `%LOCALAPPDATA%` 下布置链接）
3. 这个接口能否被用来**覆盖**一份已经有效的许可证，让产品变成不可用？
4. 未授权状态下，任何人都能调用它。这构成什么风险？
5. 返回的 JSON 里有没有泄露本机信息（机器码除外）？
