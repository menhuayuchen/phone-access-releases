## 1. 部署形态

```
客户电脑（Windows 10/11，x64）
├── %LOCALAPPDATA%\PhoneAccess\         ← 安装目录（约 129 MB，349 个文件）
│   ├── screen-server.mjs               ← Node HTTP 服务（主进程）
│   ├── runtime\node.exe                ← 自带 Node v24.21.0（不改用系统 Node）
│   ├── capture.exe                     ← 抓屏（GDI BitBlt / PrintWindow）
│   ├── input.exe                       ← 鼠标键盘注入
│   ├── audio.exe                       ← 音频采集
│   ├── supervise.ps1                   ← 守护进程（每 8 秒检查，卡死则重启）
│   ├── install.ps1 / selfcheck.ps1 / licence.ps1 / entry.ps1
│   ├── screen.key                      ← 32 位十六进制访问密钥（明文，文件权限继承目录）
│   ├── licence.json                    ← 许可证（存在则说明已授权）
│   ├── licence.state.json              ← 校验结果（供 Node 读）
│   └── product.config.json             ← 唯一的配置文件
├── %LOCALAPPDATA%\DshInput\            ← 高权限注入器目录（input.exe + 计划任务）
└── 桌面\手机远程\                       ← 客户入口（启动/自查/停止/手机入口 四个快捷方式）
```

两个计划任务（登录时自动启动 / 高权限注入器）。

## 2. 网络暴露面

| 监听地址 | 端口 | 谁在听 | 用途 |
|---|---|---|---|
| `127.0.0.1` | 8642 | 另一个产品（DSH，**客户的包里不启用**） | — |
| `127.0.0.1` | 8650 | tunnel-proxy | DSH 的门（客户包里不启用） |
| `127.0.0.1` + tailnet IP + 局域网 IP | **8660** | `screen-server.mjs` | **手机访问的全部入口** |
| tailnet IP | 443 | Tailscale serve | 把 `https://<机器名>.ts.net/` 转发到 127.0.0.1:8660 |

**永远不绑 `0.0.0.0`。**

防火墙规则：入站放行 8660 仅限 `100.64.0.0/10`（Tailscale 网段），并显式拒绝 10/8、172.16/12、192.168/16。

## 3. 信任边界

```
[ 手机浏览器 ] --Tailscale 私有网络（加密）--> [ tailnet IP:8660 ]
                                                      |
                                            screen-server.mjs
                                                      |
                              ┌───────────────────────┼──────────────────────┐
                        [ 画面帧 ]              [ 输入注入 ]           [ 命令执行 ]
                              |                       |                     |
                       capture.exe               input.exe          powershell.exe
                       （读取屏幕）          （写入鼠标键盘）      （在电脑上执行命令）
```

**关键点：** 拿到访问密钥 `k=` 的人，等同于坐在这台电脑前——能看屏幕、能操作鼠标键盘、**能执行 PowerShell 命令**。

## 4. 鉴权机制

- 密钥：32 位十六进制（128 bit），首次安装随机生成，明文存 `screen.key`
- 三种携带方式：`?k=<key>` 查询参数 / `screen-key=<key>` Cookie / 来自本机回环地址
- 失败计数：同一来源 10 分钟内错 8 次 → 锁 10 分钟，并写 `screen-auth.log`
- 密钥可通过桌面「手机入口」自助轮换

## 5. 许可证机制

- 离线的。**没有任何服务器**，所以无法吊销已签发的许可证
- 机器码 = SHA256(CPU ProcessorId + 主板序列号/产品名) 前 16 位，格式 `XXXX-XXXX-XXXX-XXXX`
- 签名：RSA-2048 / SHA-256，私钥在卖家机器上（不在产品包内），公钥内嵌在产品里
- 签名原文：`name\nmachine\nissued\nexpires(空→never)\nedition\nver`（LF 连接），**PowerShell 侧和 Node 侧各实现了一份**
- 未授权时**软停**：页面照常打开（显示机器码和购买方式），但画面流和输入接口返回 402

## 6. 许可证的两种安装方式

1. **文件**：`licence.json` 放进 `%LOCALAPPDATA%\PhoneAccess\`
2. **粘贴**：在手机的未授权页面上粘贴一段文字 → `POST /licence` → 服务端验签 → 写 `licence.json`

粘贴接口接受三种形态：完整 JSON / 单行 JSON / base64(JSON)。

## 7. HTTP 接口清单

> ⚠️ **订正（原版这里写错了）**：原来的表格把 `/health`、`/licence`、`/manifest.json` 等标成"不需要密钥"。
> 实际上**鉴权闸门在第一道，比许可证闸门更早**：所以这些路径仍然需要密钥。
> 「不需要」只是"不需要**许可证**"（未授权也能访问），不是"不需要密钥"。
> 下表已按代码实际行为订正。

鉴权分三层，行为不同：

| 层 | 覆盖的路径 | 是否需要密钥 |
|---|---|---|
| **A. 普通层** | `/health`、`/licence`（GET/POST）、`/manifest.json`、`/sw.js`、`/icon-*`、`/branding/*` | 远程要；**本机回环免** |
| **B. 严格层**（不吃本机豁免） | `/input`、`/mode`、`/unblock`、`/showdesktop`、`/rtc-on`、`/rtc-off`、`/rtc-quality`、`/sources`、`/cursor` | **一律要** + 同源校验 |
| **C. 最严层** | `/`、`/frame.jpg`、`/stream` | **一律要**（无本机豁免） |
| — | `/exec` | **一律要** + 必须 `application/json` |

许可证闸门（软停）在鉴权之后，只影响 A 层里的 `/`、`/frame.jpg`、`/stream` 等；A 层的
`/health`、`/licence`、`/manifest.json`、`/sw.js`、`/branding/*` 是**许可证豁免**的
（未授权客户要能打开页面看到机器码和购买方式）。

| 方法 | 路径 | 鉴权层 | 许可证豁免 | 作用 |
|---|---|---|---|---|
| GET | `/` | C | 否 | 手机页面（约 71 KB HTML），并下发 cookie |
| GET | `/health` | A | **是** | 存活状态 + 统计（**含前台窗口标题**） |
| GET | `/licence` | A | **是** | 许可证状态 + 机器码 + 购买入口信息 |
| POST | `/licence` | A | **是** | 提交许可证文本，验签后落盘 |
| GET | `/manifest.json` | A | **是** | PWA 清单（`start_url` 带密钥） |
| GET | `/sw.js` | A | **是** | Service Worker（不做缓存） |
| GET | `/icon-*.png`、`/branding/*` | A | **是** | 图标 / 收款码 |
| GET | `/frame.jpg` | C | 否 | 单帧 JPEG |
| GET | `/stream` | C | 否 | MJPEG 流 |
| GET | `/cursor`、`/sources` | B | 否 | 光标形状 / 窗口列表 |
| POST | `/input` | B | 否 | 鼠标键盘注入 |
| POST | `/mode` | B | 否 | 切换抓屏源/模式（宽度已钳制到 ≤ 采屏宽） |
| POST | `/unblock`、`/showdesktop` | B | 否 | 抢前台 / 最小化所有窗口 |
| POST | `/rtc-on`、`/rtc-off`、`/rtc-quality` | B | 否 | WebRTC 开关 |
| POST | `/exec` | 自有 | 否 | **在电脑上执行 PowerShell 命令**（必须 `?k=` + `application/json`） |

**未授权（无许可证）时**：`/`、`/licence`、`/health`、`/manifest.json`、`/sw.js`、`/icon-*`、
`/branding/*` 可访问；`/frame.jpg`、`/stream`、`/input` 等返回 **402**。

## 8. 打包

- 卖家用 `pack.ps1` 生成产品目录（**白名单式**：只复制清单里有的文件）
- 打包后做两项自检：生产密钥全文件字节扫描、`?k=` / `token=` 文本扫描
- 用自写的 SFX 启动器压成单个 `.exe`（`[exe][zip][32 字节尾部]`）

## 9. 已知的设计取舍（陈述，不评价）

| 取舍 | 具体做法 |
|---|---|
| 无法吊销 | 离线签名，没有服务器，所以只能靠有效期 |
| 防不住破解 | 客户端校验，理论上可改二进制绕过；目标是"防随手转发" |
| 密钥明文 | `screen.key` 明文存储，靠 NTFS 权限保护 |
| 128 bit 密钥 | 32 位十六进制 = 128 bit。（代码注释里有一处写"64 bit"，是旧文案，与实际不符） |
| 信任本机回环 | 来自 127.0.0.1 的请求跳过**普通层**鉴权（本机脚本要读 `/health`）。`/exec`、`/`、`/frame.jpg`、`/stream` 不吃这个豁免；`/input` 等 9 个危险接口也不吃 |
| 命令执行是特性 | 客户是电脑的所有者，不是攻击对象；`/exec` 是给作者自己用的高级功能 |
| 计划任务权限 | **主任务**（开机自启 + 每 2 分钟守护）是 `RunLevel Limited`；**注入器任务**才是 `RunLevel Highest` |

> 订正：本节原写"主任务 RunLevel Highest"，与代码不符。实际见上表最后一行。
