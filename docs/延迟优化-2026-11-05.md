# 延迟优化记录（2026-11-05）

## 本轮落地

1. **输入路径**：指针移动批处理 25ms→8ms；click/down/up/wheel 立即发送（不再等批处理）。
2. **传输**：H.264 WebSocket 升级时显式 `setNoDelay(true)`（关 Nagle），小包不再凑包。
3. **编码**：NVENC 零延迟档（zerolatency/CBR/lookahead 0/delay 0/surfaces 2）。
4. **原生 2560 零拷贝**：`ddagrab` d3d11 帧直喂 NVENC（无 hwdownload/scale），实测 2560×1600@60 约 **7% CPU**；
   设备解不动时页面提示并自动回 1920×60。
5. **回退记录**：`hardwareAcceleration:'prefer-hardware'` 与 2ms 分片在部分手机造成花屏/抽搐，已回退。

## 实测数据

| 项 | 数值 |
|---|---|
| 2560×1600@60 零拷贝编码 | 59.67 fps、23.8 Mbps、CPU ~7% |
| 1920×1200@60 CPU 缩放路径 | ~140% CPU（无零拷贝时的旧路径） |
| 页面解码 | WebCodecs + VideoFrame 直通 `<video>`（GPU 合成） |

## 仍未解决（传输层）

TCP WebSocket 的队头阻塞是跨外网延迟主因。可选路线：
- **WebTransport(HTTP/3/QUIC)**：需要 TLS 证书与 HTTP/3 服务端，浏览器支持较好；
- **WebRTC 视频轨**：当前 `@roamhq/wrtc` 不含 H.264 编码器，无法直接复用现有 H.264 管线；
- **自研 UDP + WebRTC/WebTransport 中转**：工程量最大。

结论：传输层改造单独立项，不在稳定版上试错。
