# 轻屏 1.0.19 更新说明

> 本版起因：用户在 Windows 虚拟机里实测 1.0.18，报了四件事：
> ① 安装包里的 Sunshine（高性能组件）会卡住安装；② 安卓虚拟机里清晰模式不可用；
> ③「调分辨率」那一栏是空的；④ 开了 30 Mbps 实际只有 11 Mbps（查证为帧率/内容限制，非 bug）。
> 另外修复了「同一 Wi-Fi 地址连不上」的判定与验证（校园网/公共 Wi-Fi 设备隔离）。

## 安装器（重点修复）

- 高性能组件（Moonlight / Sunshine）改为**可选、默认不安装**：第 11 步问一次
  「现在安装吗？[Y=装 / N=跳过，15 秒后自动跳过]」；不选就跳过，网页模式完全不受影响。
- **没有网络时自动跳过**高性能组件。
- 这一步总超时 5 分钟；超时会连同它拉起的 `msiexec` 一起结束，继续后面的步骤，不再卡死。
- 无人值守安装（`-NoPause`）默认跳过；要显式安装可加 `-HighPerformance`。

## 清晰模式（虚拟机 / 远程桌面 / 锁屏）

- 服务端按**真实运行结果**判断清晰模式是否可用：编码器连续两次秒退 → 暂不可用（60 秒后自动重试），
  出第一帧 → 恢复可用。不再用"启动探测"一锤定音（锁屏/刚开机时 ddagrab 会短暂失败，会误伤正常机器）。
- 页面：加载时先问一次可用性，已知不可用 → 直接进**流畅**并说明原因，不再先黑屏 8 秒；
  运行中失败自动切回流畅并提示倒计时；修复「清晰→低频→再清晰」来回跳。
- 设置 → 画质与流量 显示「清晰模式：可用（编码器 nvenc/mf）」或「暂时不可用 —— 原因」。

## 串流游戏（Moonlight）

- 检测到本机没装 Sunshine 时，新增「安装高性能组件（用安装包自带的，约 1–2 分钟）」按钮：
  用包内 MSI **本地安装、不需要联网**；安装时电脑弹一次管理员授权；装完自动刷新为「已就绪」。
- 安装状态/失败原因在按钮旁实时显示；安装失败不影响网页模式；安装包没带组件时明确提示。

## 同一 Wi-Fi 地址

- 新增**手机侧可达性探测**：打开 设置 → 串流玩游戏 时，页面会从手机这边实际连一次
  `http://<局域网IP>:47989`：
  - 通 → 显示「✓ 手机这边能连到 x.x.x.x（同一个 Wi-Fi 可以用）」；
  - 不通 → 提示原因（校园网/公共 Wi-Fi/公司网禁止设备互访，或手机不在同一网段），
    并建议改用 Tailscale 地址或电脑热点。
- 打开「允许同一 Wi-Fi 串流」后**自动验证**：等防火墙规则生效，再从手机侧探测，
  显示「✓ 已放行，且手机这边能连到 …」或「已放行，但手机这边连不上 …（网络隔离/不同网段）」。
- CSP 的 `connect-src` 只额外放行**本机当前局域网 IP 的 47989 端口**（不放开任意 http 源；
  VMware/Hyper-V 等虚拟网卡仍排除）。

## 其他

## 追加修复（2026-11-08 傍晚，仍为 1.0.19，替换发布）

**开机后要等很久才可用 / 以为服务没自启**

- 根因：开机时 Tailscale 往往还没就绪（实测这次 90 秒），`start-screen.ps1` 取不到 tailnet 地址就直接退出，
  导致这段时间 8660 完全不监听；守护进程要等 Tailscale 给出地址后才重启服务。
- 修复：
  1. **Tailscale 未就绪时先只绑 127.0.0.1 启动**（`tailscale serve` 的转发目标就是回环，Tailscale 一就绪手机 HTTPS 立刻可用）；
     守护进程拿到 tailnet 地址后自动重启补上 tailnet 监听。安全姿态不变（仍然不开局域网）。
  2. `Get-TailscaleInfo` 里 `tailscale ip -4` / `status --json` 加 **5 秒超时**（实测该命令在 Tailscale 初始化时会阻塞 47 秒，把守护循环卡住）。
  3. 自启去重：两个历史遗留的自启任务都指向 `run-autostart.vbs`、各每 2 分钟跑一次 → `autostart.ps1` 加 70 秒去重；
     `install.ps1` 在注册任务后清理重复任务（只保留 `DSH Phone Access`）。
- 实测：本机模拟"Tailscale 未就绪"时，画面服务只监听 `127.0.0.1`、不再退出；超时工具 2 秒准时返回；重复触发不再写日志。

**附：本机电源设置（与产品无关，已一并处理）**

- 发现「高性能」方案把**插电时最小处理器状态**设成了 100%（CPU 钉在满睿频），已改回 5%/5%（AC/DC），并清理重复自启任务。
**修：清晰模式一旦失败就再也切不过去（死锁）**

- 现象：点「清晰」立刻跳回流畅；服务端 `/h264-status` 一直 `capable=false`。
- 根因：上一版加的"能力锁"只在一处清（出帧时），冷却期结束后仍保持 `false`；
  页面看到 `capable=false` 就拒绝启动清晰模式 → 死锁（只有出帧才会变 true，但页面不给启动）。
- 修复：
  1. 页面三处（启动闸门、看门狗、初始化预判）只在 `retryInMs > 0`（真正冷却期内）才拦截；冷却结束允许重试。
  2. 服务端 `/h264-status`：冷却期结束后把过期的 `capable=false` 清成"未知"（`null`）、清空原因。
  3. 冷却提示改成切回流暢后延迟 0.9 秒再显示，避免被流畅模式的刷新清掉。
- 实测：点清晰正常进 h264（56fps）；模拟 30 秒冷却时正确切回流暢并显示倒计时；冷却结束后可再次切回清晰。
**修：安装器第 2 步误杀（连不上 login.tailscale.com 就整包中止）**

- 现象：在 VMware 虚拟机/只有 IPv4 的机器上安装，第 2 步报
  「连不上 Tailscale 登录服务器（login.tailscale.com:443）」→ 安装直接中止。
- 根因：旧检查只测 `login.tailscale.com:443`（网页登录入口，不是控制平面），
  6 秒不通用**硬失败**中止。实测本机能用 Tailscale 是走 IPv6（2606:b740:1:20::102），
  虚拟机 NAT 没有 IPv6、IPv4 又被网络限制时就必然失败。
- 修复：
  1. 若 Tailscale **已安装且已登录**（`BackendState=Running`）→ 直接通过，不再探测；
  2. 否则测 `controlplane.tailscale.com` 与 `login.tailscale.com`，**IPv4/IPv6 任一能通即通过**
     （整体上限 15 秒，避免网络极差时卡 1 分钟）；
  3. 这项从"硬失败"改为**软门槛**：仍失败只警告、继续安装（装完在手机设置里能看到 Tailscale 状态）；
  4. 文案区分"已登录/能连上/都连不上"，不再一句"连不上就装不了"。
- 实测：本机干跑第 2 步显示「Tailscale 已安装并已登录（跳过网络探测）」，全程退出码 0。
