# 环境矩阵：这台机器到底能不能装

> 用途：接单前 10 分钟判断「该不该接、要不要加价、合同要写什么」。
> 面向：销售 / 售前（不需要懂技术，照着查、照着读结论即可）。
> 基准机器：`LAPTOP-0FIMMV7J`（Windows 11 专业版 build 26200 / 2560×1600 / 150% 缩放）；下文说「本机」都指这台。
> 实测日期：2026-10-28。依据：`phone-access\check-health.ps1`、`start-phone-access.ps1`、`start-screen.ps1`、`install-elevated-input.ps1`、`harden-firewall.ps1`、`手机入口速查.md`、`README.md`、`phone-access-product\survey.ps1`。

**一句话结论**：这套东西不难装，但它有 6 条「机器不满足就免谈」的硬条件，和 12 条「能装但要先说清楚、可能要加钱」的软条件。干净的家用 Win10/Win11 电脑是绿单；公司发的域内电脑、没管理员权限的电脑、机房服务器是红单。

## 0. 怎么用（10 分钟判定法）

```
第 1 步（3 分钟）  在客户机上用「客户自己的账号」登录，跑 survey.cmd（只读；拿不到管理员也能跑，但会少几项）
                    ↓
第 2 步（2 分钟）  看它最后的结论：可以装 / 有条件装 / 别接
                    ↓
第 3 步（3 分钟）  人工补查 survey 没查的 3 项：UAC、登录会话、运行时依赖（命令见 §5.2 与 §8.2）
                    ↓
第 4 步（2 分钟）  按 §2 硬门槛定生死，按 §3 软门槛数条数定报价（§6）
```

**定档规则**

| 情况 | 结论 | 报价动作 |
|---|---|---|
| 硬门槛有任意 1 条不满足 | **拒单**（或改方案：换机器 / 客户 IT 出书面许可） | 不报价 |
| 硬门槛全过 + 软门槛 0~1 条 | **绿单**，可以装 | 标准价（半天交付） |
| 硬门槛全过 + 软门槛 2~4 条 | **黄单**，能装 | 标准价 + 半天（现场处理项） |
| 硬门槛全过 + 软门槛 ≥5 条 | **灰单**，先实测再报价 | 先做 30 分钟远程实测，再定 |

**拒单话术**（不要跟客户讲技术细节，说这三句就够）
> 「您这台电脑是公司统一管理的，我们的远程方案需要改动防火墙和后台服务，会被公司策略覆盖掉，装了也不稳定。建议用在您自己的电脑上，或者请公司 IT 出一份书面许可，我们再进场。」

## 1. 实测基线：这一单为什么敢接

下面全部是本机真实测量值，不是推测。销售可以把这一段理解为「最坏情况我们已经踩过一遍了」。

| 项 | 实测值 | 怎么读 |
|---|---|---|
| 操作系统 | Windows 11 专业版，build 26200，64 位，未加域（WORKGROUP） | 家用/个人机典型环境 |
| 杀毒软件 | `Lenovo Anti-Virus powered by Huorong Security`（联想电脑管家内置火绒引擎）+ `Windows Defender` 实时保护 **开启** | **两个杀软同时在线** |
| 注入器状态 | 计划任务 `DSH Input Injector` 运行中（RunLevel=Highest），`input.log` 最近 3 条启动行均为 `integrity=high` | 注入器以管理员权限运行 |
| 注入实测 | `/health` 返回 `input={"connected":true,"sent":12218,"errors":0,"blocked":0}` | **零错误、零被挡** |
| Defender 历史 | 只拦过「脚本形态」：`HackTool:PowerShell/EmpireGetScreenshot.C`（命中 `capture-screen.ps1`），编译成 `capture.exe` 后不再触发 | 决定了交付物必须是 exe，不能是 .ps1 |
| 显示 | 物理 2560×1600，`AppliedDPI=144`（150%） | 缩放不是 100% |
| 缩放校正 | `cursor-probe.log` = `pmv2=True x=1624 y=1005`，与 `/cursor` 接口返回一致（check-health 判定阈值 ≤2px） | **DPI 已被机制解决** |
| 登录会话 | `query session` 显示 `console 1 Active` | 依赖「已登录桌面」 |
| 电源 | 待机 `0x00000000`（从不睡眠） | 已按交付要求改过 |
| UAC | `ConsentPromptBehaviorAdmin=0`、`PromptOnSecureDesktop=0` | 提权不弹窗（见 §3 S5） |
| Tailscale | Running，`<本机Tailscale地址>`，key 2027-04-19 到期 | 入口依赖它 |
| 防火墙 | 3 条规则就位；Domain/Private/Public 全 Enabled、默认入站 Block | 局域网已封，只留 tailnet |
| 运行环境 | PowerShell 5.1、ExecutionPolicy=Restricted、.NET 4.8+ | 必须用 `survey.cmd` 这类 .cmd 包装 |

### 两个必须记住的实测结论

**结论 A：火绒 + Windows Defender 同时在场，注入器正常工作 → 这条路能走通。**
证据：两个杀软都在安全中心注册（`root\SecurityCenter2` → `AntiVirusProduct`），Defender 实时保护 `RealTimeProtectionEnabled=True`，同时注入器 `errors:0 / blocked:0`，累计已发送 12218 次输入事件。
**关于「需不需要排除项」——本机不需要排除项就能跑通。** 做这个判断时当前进程没有管理员权限，读不到排除项清单（系统回 `N/A: Must be an administrator to view exclusions`），所以我不能声称「本机没有排除项」；我只能说明：**在没有证据表明依赖排除项的情况下，注入器已经稳定工作**。
建议仍加排除项（见 §3 S1），理由是「降低复发概率」，不是「不加就不能用」。这两句话对客户的意思完全不同，销售不要说错。

**结论 B：150% 缩放已解决，不是风险。**
证据：`capture.exe` / `sources.exe` / `input.exe` 都声明了 `PER_MONITOR_AWARE_V2`，本机 `cursor-probe` 用自己的读数与画面服务的 `/cursor` 接口对照，差值 ≤2px 判为正常；本机探针读数 `x=1624 y=1005`，与接口一致。
所以 150% 缩放这一条在矩阵里标「已解决」，**不参与加价，只留一句口头提示**。

## 2. 硬门槛（不满足 → 必须拒单或改方案）

共 **6 条**。判断标准是「这台机器自己改不动」——不是我们多花时间能解决的事。

| 编号 | 门槛 | 检查方法（一行命令 / 注册表） | 不满足时会怎样 | 是否必须拒单 |
|---|---|---|---|---|
| **H1** | Windows 10 2004（build 19041）及以上，**64 位** | `Get-CimInstance Win32_OperatingSystem` 看 `BuildNumber`、`OSArchitecture`（或 `winver`） | 老的网络/DPI 能力缺失，抓屏与端口检测跑不起来；32 位系统连编译好的 exe 都加载不了 | **是**。Win7/8/8.1、Server 2012/2016、32 位一律拒 |
| **H2** | 客户账号**在管理员组**，且装机时能提权一次 | `Get-LocalGroupMember -Group Administrators`；当前是否提权：`whoami /groups` 找 `Mandatory Label\High` | 装不了 Tailscale、加不了防火墙规则、注册不了「最高权限」注入任务 → 只能看不能控，等于半成品 | **是** |
| **H3** | 机器**没有被域控 / MDM 统一管控** | `Get-CimInstance Win32_ComputerSystem` 看 `PartOfDomain`；`dsregcmd /status` 看 `AzureAdJoined / EnterpriseJoined / DomainJoined`；MDM：`Get-CimInstance -Namespace root/cimv2/mdm/dmmap -ClassName MDM_DevDetail_Ext01`（返回 0 条=没被管） | 组策略会覆盖防火墙规则、计划任务、执行策略；今天的配置明天被 IT 推回来，故障无法归因，责任扯不清 | **是**（除非客户 IT 出书面许可并承诺不改策略） |
| **H4** | 能访问外网 `login.tailscale.com:443` | `Test-NetConnection login.tailscale.com -Port 443` | 手机端唯一入口是 Tailscale。连不上=客户端永远连不上，且我们**不开放公网端口**作为退路 | **是** |
| **H5** | 客户接受「必须有人登录过桌面并保持登录」 | `query session`（要有 `console ... Active`）；任务计划：`Get-ScheduledTask -TaskName 'DSH Phone Access'` 看 `Principal.LogonType`（=Interactive） | 注销 / 重启后停在登录界面 → 后台服务不运行，手机一片黑，客户会认为「你们的产品坏了」 | **是**（这是架构决定的，见 §4 U6） |
| **H6** | 系统盘可用空间 **≥10 GB** | `Get-PSDrive C` 看 `Free`/1GB | 录屏与缓存写不下；更新的时候装不上 | **先清盘**；清不出来则拒单 |

> 依据：`install-elevated-input.ps1:34-41`（无管理员直接退出）、`harden-firewall.ps1:30-34`（无管理员 exit 1）、`survey.ps1:48-81`（版本/域/管理员三条硬判定）、`README.md:286-287,304`（登录会话与注销限制）、`手机入口速查.md:4`（手机必须开 Tailscale）、`check-health.ps1:30-46`（计划任务存在性与 LogonType 依赖）。

**两条容易吵起来的判定，先记下来**

1. **MDM 不算「软提醒」，算硬门槛。** `survey.ps1:64-65` 目前把 MDM 归到「提示」一档，建议在接单层面升级为硬门槛：Intune 能下发防火墙与应用控制策略，效果等同于域控，事后补救成本极高。
2. **「在管理员组但没提权」不算硬门槛。** 这是最常见的情况（本机就是这样：`ccj` 在 Administrators 组，当前进程是 Medium）。它能装，只是需要现场点一次 UAC —— 归 §3 S5。

## 3. 软门槛（能装，但要告知客户 / 可能要加价 / 要写进合同）

共 **12 条**。每一项的具体检查命令见 §5.1 同一编号那一行；这张表只讲「后果、能不能现场救、要不要加钱」。

| 编号 | 软门槛 | 风险后果 | 能否现场解决 | 是否计入报价 |
|---|---|---|---|---|
| **S1** | 装了第三方杀软（火绒 / 360 / 腾讯管家 / 卡巴 / ESET 等） | ①文件查杀可能隔离 `capture.exe` / `input.exe`（有 `.bak` 自动恢复，但不保证）②**网络防护 / 联网控制**可能拦 `node.exe` 监听端口 → 手机打不开 ③行为防护可能在点「允许」之前就拦掉注入 | 能：加排除项 + 关掉该软件的「网络防护」对 node 的拦截；①有实测兜底（结论 A），②③必须现场做一次真实点击验证 | **是**，+0.5 天（含客户 IT 沟通） |
| **S2** | 显示缩放 ≠100%（含两块屏缩放比例不同） | 点击坐标偏移，客户会觉得「点不准」 | **已解决**：程序声明 PMv2 + `cursor-probe` 自校正（本机 150% 实测通过） | **否**（仅多屏不同比例时 +0.5h 复验） |
| **S3** | 接了 2 块及以上显示器 | 抓屏默认按「整屏 / 主屏 / 指定窗口」三档，客户想看的可能是第二块屏，或只想看某个窗口 | 能：页面里切换 `/mode`；要提前问客户「你要看哪一块」 | **是**，+0.5h 沟通与调试 |
| **S4** | 锁屏 / 屏保要密码 / 睡眠 / 休眠 | 锁屏时画面只有锁屏界面（Windows secure desktop，系统行为，不是 bug）；睡眠时**完全连不上** | 能：电源计划改「从不睡眠」、关屏保；但**锁屏后看不到桌面内容这条改不了** | **是**，+0.5h；并且必须写进合同 |
| **S5** | UAC 保持 Windows 默认（`ConsentPromptBehaviorAdmin=5`） | 提权弹窗 `consent.exe` 跑在 SYSTEM 完整性，弹窗在屏幕上时**所有远程点击失效**，看起来像「卡死了」 | 能，但代价大：把 `ConsentPromptBehaviorAdmin` 设为 `0`（提权不弹窗）= 降低安全性，**必须客户书面同意**。本机已设为 0 | **是**，+0.5h；写成「安全放宽」条款 |
| **S6** | 前台窗口是管理员权限程序（厂商工具、任务管理器、杀软主界面） | UIPI 拦注入，光标不动 | **已解决**：注入器以管理员权限运行（`integrity=high`），UIPI 管不着。代价是装机时要点一次 UAC | **否**（一次性动作，含在基础交付里） |
| **S7** | Tailscale 设备 key 到期 | 到期当刻手机突然全部连不上，客户第一反应是「你们的系统崩了」 | 能：后台续期或关掉 key expiry。本机 key 到 **2027-04-19** | **是**，计年度维护 |
| **S8** | Windows 自动更新后重启、停在登录界面 | 服务不运行 → 手机黑屏 | 能：约定「重启后客户手动登录一次」（最省事），或配自动登录（降低安全性，要客户同意） | **是**，计年度维护或写进 SLA |
| **S9** | 硬件偏弱（内存 <8 GB / 老 CPU / 核显 / 4K 屏高负载） | 帧率低、画面糊、点一下要等 | 部分能：降分辨率 / 省流量模式；真不行只能换硬件 | **是**，先实测再报价 |
| **S10** | 端口 8642 / 8650 / 8660 被别的软件占用 | 起不来 | 能：改端口（要同步改防火墙和二维码） | **是**，+0.5h（改端口是体力活） |
| **S11** | 客户网络是运营商大内网（CGNAT）/ 企业网限制 UDP | Tailscale 打洞失败 → 走中继 → 延迟 200~500ms，能连但不好用 | 能连（这点很重要：**能用**），体验要提前说清 | **是**，+1h 实测与调优 |
| **S12** | 高分屏 / 超宽屏（4K、3440×1440 等） | 抓屏宽度写死 2560，文字会比原生屏糊一点 | 能：调抓屏宽度参数 | **否**，口头告知即可 |

> 依据：`README.md:105-108`（150% + PMv2）、`README.md:122-124`（AMSI 拦脚本，故用编译 exe）、`README.md:299-305`（锁屏/Defender/注销三条残余风险）、`README.md:1293-1304`（`consent.exe` 在 SYSTEM 完整性 + `ConsentPromptBehaviorAdmin=0`）、`README.md:574-577,608-623`（低完整性 vs UIPI）、`手机入口速查.md:67-68`（锁屏黑屏、UIPI）、`check-health.ps1:190-217`（DPI 探针）、`start-screen.ps1:103`（抓屏宽度 2560）。

## 4. 已知不可支持的场景（照样例说原因）

| 编号 | 场景 | 为什么做不到 | 对应硬门槛 |
|---|---|---|---|
| **U1** | 公司发的**已加域**电脑 | 组策略覆盖防火墙、计划任务、执行策略；改动会被 IT 推回 | H3 |
| **U2** | **Intune / MDM** 统一管控的设备 | 同上，且可能禁止安装非商店软件 | H3 |
| **U3** | 只有**标准用户**权限、拿不到管理员 | 装不了 Tailscale、加不了防火墙规则、注册不了高权限注入任务 | H2 |
| **U4** | **Win7 / Win8 / 8.1 / Server 2012 及更老**，或 32 位系统 | 网络 cmdlet、DPI 感知能力、.NET 运行时都不满足 | H1 |
| **U5** | **RDS 多会话 / VDI / Citrix / 云电脑** | 抓的是「会话桌面」不是「本机桌面」；多用户抢占输入；没有稳定的控制台会话 | H5（架构） |
| **U6** | **机房服务器 / 无人值守机**：要求「开机不登录也能远程」 | 整套服务是用户会话级的：计划任务 `LogonType=Interactive`、登录触发 → **注销/没人登录就不运行** | H5（架构，改不了） |
| **U7** | 需要**看到锁屏后的内容**，或需要**点掉 UAC 弹窗** | 锁屏是 secure desktop，抓不到；UAC 弹窗在 SYSTEM 完整性，注入进不去 | 设计边界（见 §3 S4/S5） |
| **U8** | **纯内网 / 只允许白名单出网**（医院、军工、银行前置机） | 连不上 `login.tailscale.com:443`，且我们**不开放公网端口**作为替代 | H4 |
| **U9** | 目标机不是 **Windows**（Mac / Linux / ChromeOS / 手机） | 只做了 Windows 客户端 | H1（范围外） |
| **U10** | **GHOST / 精简版 / 优化版系统** | 系统组件被删（.NET、多媒体、WMI），装上了也时好时坏，故障无法归因 | 建议重装原版系统，否则拒单 |
| **U11** | 客户坚持要**「公网直连、路由器端口映射」**方案 | 安全设计上明确不做（局域网已封、只走 tailnet），这是产品红线不是能力不足 | 不接受改设计 |
| **U12** | 一台机器**多人同时登录使用**（快速切换用户） | 只能抓当前活动会话；切到别人桌面时画面是黑的 | H5（架构） |

### 6.2 合同里必须写明的 6 条（不写＝以后必吵）

1. **必须保持登录**：锁屏可以，但注销、重启停在登录界面时不提供服务；重启后需人工登录一次。
2. **锁屏看不到桌面内容**：这是 Windows 的安全机制，不是故障。
3. **UAC 提权弹窗不可控**：屏幕上出现提权确认框时，远程点击会失效（除非按 S5 放宽 UAC，且需客户书面同意）。
4. **手机端＝整机权限**：能读写文件、能执行命令、审批提示是关闭的。手机丢失等同电脑丢失；密钥泄漏时用 `rotate-key.ps1 -Force` 立即吊销所有旧链接与已登录设备（128 bit 随机密钥）。
5. **不走公网**：不做端口映射，全部流量走 Tailscale（WireGuard 加密，但页面本身是 HTTP 不是 HTTPS）；客户不能要求「公网直连」。
6. **杀软责任边界**：我们负责加排除项和自愈（`capture.exe` 被隔离会从 `.bak` 恢复），但不承担「客户新装/升级安全软件后不可用」的可用性承诺。

## 7. P0：交付形态的前置条件（不属于客户环境，但决定这单能不能做）

这一条**不是**客户机器的问题，是我们自己的问题，但必须在报价前解决，否则接了就出不了货。

**现状**：整套脚本把本机路径写死在代码里 ——
- `start-phone-access.ps1:4-6`：`$cli = 'D:\deepseek\resources\runtime\cli\bin\dsh.cmd'`、`$node = 'C:\Users\ccj\.dsh\dsh-runtimes\...\node.exe'`、`$py = '...\python.exe'`
- `start-screen.ps1:7`：python 路径同上写死
- 启动项 `DSH Bridge Server.lnk` / `DSH Record Server.lnk` 指向 `D:\deepseek\resources\runtime\primary-runtime\...\node.exe`
- 注意上面两处 node 路径**并不一致**（一个在 `.dsh\dsh-runtimes`，一个在 `D:\deepseek\resources\runtime`），现在是靠「都存在于本机」糊过去的
- 本机实测 `Get-Command node` 返回 **False**：node 根本不在 PATH 上，全靠绝对路径调用；客户机上不会这么巧

**结论**：交付到任何客户机之前，必须先做成「自包含安装包」——把 node / python（或改成不依赖它们的实现）打进包里、路径参数化、二维码生成不依赖系统 python。**survey.ps1 目前不检查这一项**（见 §5.2 第 4 项）。
在没做完打包之前：只能做「本机演示」或「同型号同镜像机器」的单子，不能对陌生客户承诺上门安装。
