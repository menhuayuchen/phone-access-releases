# 定时休眠/唤醒：休眠日期与唤醒日期分开设置（2026-11-13）

## 1. 问题

页面「设置 → 功能 → 定时开关机」原来一条「仅一次」规则只有一个日期（`date`）：

- 休眠 11-13 23:00、唤醒 11-14 07:30 时，日期只能填 11-13，唤醒会被排到 11-13 07:30（已经过去）；
- 用户没法把休眠和唤醒放在不同日期，跨夜规则实际上不能正确设置。

## 2. 新模型

每条规则新增两个独立字段：

```json
{
  "id": "r...",
  "mode": "hibernate",
  "repeat": "once",
  "offDate": "2026-11-13",
  "wakeDate": "2026-11-14",
  "offTime": "23:00",
  "wakeTime": "07:30",
  "enabled": true,
  "date": "2026-11-13"
}
```

- `offDate`：休眠/关机日期；`wakeDate`：唤醒日期；两者可以不同。
- `date` 保留为**兼容旧规则/旧页面**的别名（= `offDate`）。
- `daily/weekdays/weekend` 仍只用车时间（日期字段清空）。

### 页面（手机）

- 编辑器现在有两个日期框：「休眠日期」「唤醒日期」；只有「仅一次」时可选，其他重复方式置灰。
- 默认联动：
  - 选「仅一次」自动把休眠日期设为今天；
  - 唤醒时间不晚于休眠时间（例如 23:00 → 07:30）→ 唤醒日期自动 +1 天；
  - 唤醒时间晚于休眠时间（例如 23:00 → 23:45）→ 唤醒日期同一天；
  - 用户仍可手动改唤醒日期。
- 校验：
  - 选「仅一次」必须有休眠日期，且时间不能已经过去；
  - 有唤醒时间必须有唤醒日期，且唤醒时间点必须晚于休眠时间点（跨夜请选次日）；
  - 时间相同仍拒绝。
- 规则列表显示成 `仅一次 11-13 23:00 休眠 → 11-14 唤醒 07:30`，不再只显示一个日期。
- 快捷规则：
  - 一小时后休眠/关机：`offDate` = 今天（或跨天后的日期）；
  - 自检（2 分钟后休眠/4 分钟后唤醒）：分别填两个日期，跨午夜也对；
  - 工作日/每天：日期为空。

### 服务端（screen-server.mjs）

- `/power/apply` 的 `normRules` 接受 `offDate`/`wakeDate`；旧数据没有时从 `date` 回退。
- 仅一次：校验 offDate、off 时间未过去；有唤醒时校验 wakeDate，并保证 `wakeAt > offAt`。
- 旧规则只有 `date` 且唤醒时间更早时，自动推断 `wakeDate = date + 1 天`（修复历史跨夜规则）。
- 状态接口原样返回规则，页面自身对旧规则用 `offDate || date` 显示。

### 引擎（power-apply.ps1）

- `Normalize-Rules` 读出 `offDate`/`wakeDate`；旧规则回退 `date` 并按时序推断次日。
- 校验：仅一次必须有 offDate、off 时间未过去；有唤醒必须有合法 wakeDate 且唤醒晚于休眠。
- `New-OffTrigger` 用 `offDate`；`New-WakeTrigger` 用 `wakeDate`（不再用同一个 date）。
- 输出规则同时带 `offDate/wakeDate/date`，保持旧字段兼容。

## 3. 已验证（不注册真实计划任务）

### 3.1 页面（隔离实例，本地 Chrome）

- 切「仅一次」：休眠日期自动 2026-11-13，唤醒日期 2026-11-14（23:00→07:30）。
- 唤醒改 23:45：唤醒日期自动回到 2026-11-13（同一天）。
- 把唤醒日期手动改回同日、时间 07:30：页面拒绝，提示
  `唤醒必须晚于休眠（跨天请把唤醒日期选到次日）。`
- 改成 11-14 07:30 后「加入」成功，列表显示
  `仅一次 11-13 23:00 休眠 → 11-14 唤醒 07:30`。
- 只点了「加入」，**没有点保存并应用**，不会写系统任务。

### 3.2 服务端校验（隔离实例）

- POST 同日 23:00→07:30 的规则：HTTP 400，
  `{"ok":false,"error":"第 1 条：唤醒必须晚于休眠"}`；未写文件、未提权。

### 3.3 引擎函数（从 power-apply.ps1 提取函数，不执行主流程）

- 新跨夜规则：`offDate=2026-11-13 wakeDate=2026-11-14`；
- 旧单 date 规则：自动得到 `wakeDate=2026-11-14`；
- 同日期唤醒更早：报错 `唤醒必须晚于休眠`；
- 过去日期：报错 `休眠日期时间已经过去了`；
- 工作日规则：日期为空；
- 生成的触发器（StartBoundary 为 UTC，均为本地 23:00 / 次日 07:30）：
  - 休眠：`2026-11-13T15:00:00Z`
  - 唤醒：`2026-11-13T23:30:00Z`、`23:33Z`、`23:36Z`（+0/+3/+6 分钟兜底）

## 4. 未覆盖 / 风险

- 没有真正注册计划任务（避免测试机产生真实休眠/唤醒）；`power-apply.ps1` 的**任务注册**部分沿用原逻辑，只改了日期来源。
- 发布版/自用版都要重新打包；旧页面（缓存）仍会发单 `date`，服务端兼容，但页面看不到两个日期框——需要刷新/安装新包。
- 旧规则自动推断“唤醒日期 = 次日”只针对唤醒时间 ≤ 休眠时间的跨夜情况；如果用户原本故意想同一天更早唤醒（无意义），现在会变成次日。
