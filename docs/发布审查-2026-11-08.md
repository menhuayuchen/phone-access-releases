# 发布版审查报告（2026-11-08）

对象：`dist\LightScreen-Setup-v1.0.18-release.exe`（发布版）＋ 同版本自用版对照。
审查项：安全问题 / 个人隐私泄露 / 隐藏 bug / DSH（dsh / DeepSeek）痕迹。

---

## 一、发现的问题（都已修）

### P1 隐私：二维码库把构建机路径和用户名打进了包

发布包里 `qrlib` 目录下：

- `qrlib\bin\qr.exe`：内嵌 `C:\Users\ccj\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`
  —— **用户名 + DSH 运行时路径**；
- `qrlib\**\__pycache__\*.pyc`（65 个）：Python 字节码里带源码绝对路径
  （`C:\Users\ccj\AppData\Local\Temp\pip-target-...`），同样泄露构建机信息。

而且 `qr.exe` **产品根本没用到**（服务端用 `make-qr.py` + 系统 python 生成二维码）。

**修复**：`app/pack.ps1` 在复制 qrlib 后清掉 `bin\qr.exe`、所有 `__pycache__` 与 `*.pyc`，
并新增断言：清理后 qrlib 文件数必须 ≥50，否则打包直接报错；`*.pyc/.pyo` 加入"禁止文件"检查。
**验证**：新包 qrlib 69 个文件、pyc 0、qr.exe 0；实测 `make-qr.py` 仍能正常出二维码（420×420 PNG）。

### P2 DSH 痕迹：声音/输入组件的默认管道名还是 `dsh-audio` / `dsh-input`

`audio.exe`、`input.exe` 里仍嵌着 `dsh-audio` / `dsh-input` 字符串（旧默认值）。
脚本侧早已改成 `pa-audio` / `pa-input`，所以**功能不受影响**，但二进制里留着 DSH 字样。

**修复**：改 `app/audio.cs`、`app/input.cs` 的默认值为 `pa-*`，用 `release-tools/build-audio.ps1`
（GUI 子系统，与生产一致）重新编译，部署到生产目录并重装提权注入器（`PhoneAccess Input` 任务）。
**验证**：新二进制 20992B/20480B，`dsh` 命中 0，`pa-*` 命中 1；`/health` 显示 `input.connected=true`。

### P3 隐私（自用版）：pnpm `.bin` 垫片带构建机绝对路径

`node_modules\**\.bin\semver` 等脚本里写着
`C:\Users\ccj\Documents\deepseek-harness\default-workspace\phone-access\node_modules\.pnpm\...`。
**发布版构建的后处理本来就会删这些垫片**（所以发布包干净），自用版仍带着。

**修复**：`app/pack.ps1` 增加通用清理（两条轨道都删 `node_modules\**\.bin`）。
自用版本次未重打（自己的机器，且不影响功能），下一次打包生效。

### P4 策略不一致：发布版面板仍可打开「唤醒后不要求登录」

`mark-release.ps1` 在构建时把 `security.unlockOnWake` 强制为 false，但**页面开关仍在**：
客户点一下还是会开启（唤醒后回桌面、不需要密码），削弱锁屏安全，也和面板上
「发布版强制关闭」的文案矛盾。

**修复**（两层）：
1. 服务端：`/power/apply` 里读 `profile`，发布版把 `unlockOnWake` 一律写成 false（防旧页面缓存/直接调接口）；
2. 页面：`/power/status` 增加 `profile` 字段；发布版**隐藏该开关**，说明文案改成"仅自用版提供"。
   `PAGE_VER` 同时升到 `2026-11-08.1`（破 Service Worker 缓存）。
