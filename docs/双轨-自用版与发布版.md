# 双轨：自用版 / 发布版（2026-11-07 立）

> 一句话：**代码只有一份**，用 `app\product.config.json` 里的 `"profile"` 一个字段决定这个包是给谁用的。
> 自用版可以带实验和半成品；发布版读到一个 `release` 就整块忽略实验层，客户包里永远不会出现实验接口。

---

## 一、为什么要有这个

以前"自用版 / 发布版"只有文件名不同：两份包代码一模一样，唯一差别是发布版跑了一遍 `scrub` 去标识化。
后果是**半成品会跟着进客户包**——比如高清放大增强（OCR 重画）用户自己判断"只适合静态内容、不建议进正式版"，
但代码和开关都在包里，只是没人去开。

现在多一层**功能级分流**：发布版在代码层面就拿不到实验功能，不靠"记得关"。

---

## 二、两条轨道到底差什么

| 项 | 自用版 `selfuse` | 发布版 `release` |
|---|---|---|
| 产物名 | `dist\LightScreen-Setup-v<ver>-selfuse.exe` | `dist\LightScreen-Setup-v<ver>-release.exe` |
| 源码 | `app\` **原样**打包 | `app\` → `.release\app`，跑三段 scrub 去标识化 |
| `profile` | `selfuse` | `release`（由 `mark-release.ps1` 改这一处） |
| 实验接口 `/exp/*` | 按 `experiments.enabled` | **一律 404**（服务端把 `experiments` 当 `{}`） |
| 高清放大增强（OCR） | 可用（`?exp=ocr`） | 没有 |
| 电脑真实光标（`features.realCursor`） | 有 | **有**（已转正，不跟实验开关联动） |
| dsh / DeepSeek / 本机路径 / 密钥字样 | 保留 | 必须 0 处（出包前断言） |
| 开发脚本、日志、`.cs` 源码 | 保留 | 清掉 |
| `security.unlockOnWake`（唤醒后不要求登录） | 默认 `true` | **强制 `false`**（`mark-release.ps1` 会改并断言） |

**规则一句话**：功能转正了 → 从 `experiments` 挪到 `features`；没转正 → 只许写在 `experiments` 里。
**安全相关**的便利开关（比如 `security.unlockOnWake`，唤醒后不用 Windows 密码）一律走"自用版默认开、发布版强制关"。

**规则一句话**：功能转正了 → 从 `experiments` 挪到 `features`；没转正 → 只许写在 `experiments` 里。

## 三、怎么打

在 `D:\download\办共\phone-access-product` 根目录：

```powershell
# 自用版
powershell -NoProfile -ExecutionPolicy Bypass -File release-tools\build.ps1 -Track selfuse

# 发布版
powershell -NoProfile -ExecutionPolicy Bypass -File release-tools\build.ps1 -Track release
```

- 版本号只改 `app\product.config.json` 的 `version` 一处，`build.ps1` 会读它；传 `-Version` 且不一致会直接报错。
- 两个包的版本号、`features.realCursor` 会被脚本**回读验收**，对不上就不出包。
- **只出包，不发布**：不改版本号以外的东西、不传 Gitee/GitHub、不打 tag（发版规则 `a293ad2e`）。

## 四、代码里怎么读这几个开关

`app\screen-server.mjs` 顶部新增（每次请求现读，改完不用重启）：

| 函数 | 作用 |
|---|---|
| `liveConfig()` | 读 `product.config.json`（启动时的 `productConfig` 是快照，改配置不刷新） |
| `isSelfUse()` | `profile` 缺省或 `selfuse` → true；`release` → false |
| `featureOn(name)` | 正式功能开关；`realCursor` 缺省 **true**，只有显式 `false` 才关 |
| `expConfig()` | 实验开关；`profile=release` 时直接返回 `{}`（不挂 `/exp/*`） |

页面侧：`page.mjs` 的真光标仍然默认加载（`?exp=nocursor` 临时关），它连的是 `/ws-exp`，
门控换成 `features.realCursor`，跟 `experiments` 无关了。

## 七、二进制不来自仓库，来自「生产目录」

这是这套流程最容易踩的坑，单独列出来：

| 文件 | 从哪来 | 后果 |
|---|---|---|
| `audio.exe` / `input.exe` / `capture.exe` / `sources.exe` / `lib\NAudio*.dll` | `%LOCALAPPDATA%\PhoneAccess`（生产目录） | 只改 `.cs` 源码不部署 → **打出来的包还是旧二进制**，客户装的版本没修 |

所以改 C# 组件的顺序必须是：**改 `.cs` → 编译 → 部署到生产目录（提权，停旧进程）→ 再打包 → 再跑产品验证**。
- `audio.exe` 用 `release-tools\build-audio.ps1` 编译（默认输出 `dist\audio.exe`，`-Out` 可指定）；
- `input.exe` 见 `app\install-elevated-input.ps1`。

注意：csc 编译产物**不保证逐字节可复现**（PE 头里有时间戳），两次编译 SHA256 不同是正常的；
比对用文件大小 + 行为（`audio.log` 里 `pipe: client connected` / `rms`），不要拿 hash 当断言。

2026-11-07 的音频 EPERM 就是按这条走完的：改 `audio.cs` → `build-audio.ps1` → 提权替换 + 重启 →
`audio.log` 出现 `pipe: client connected`、`rms` 从 0 变 0.0396 → 才重打双包。

## 八、踩过的坑（别再犯）

1. **`productConfig` 这个名字别用**：`screen-server.mjs` 第 61 行已有启动快照常量，再声明一个函数会 `Identifier has already been declared`。现读的那个叫 `liveConfig()`。
2. **`.ps1` 必须 UTF-8 带 BOM**，且**绝不能写 `//` 注释**（PowerShell 当命令执行，语法检查发现不了）。
3. 发布版断言是**两段**：全文不能有 dsh/本机字样（老逻辑）+ 包里 `profile` 必须是 `release`（新逻辑）。少一段就等于没做。
4. 安装目录的 `product.config.json` 是**运行期状态**（本机有 `screen.h264.qualityFirst=true`、`screen.lan=false` 这些仓库里没有的键），
   升级代码时**不要整份覆盖**，只补 `profile` / `features`。
