# 轻屏 vs 主流远程桌面/串流方案（2026-11-12）

> 目的：把"我们到底强在哪、弱在哪"讲清楚，避免只凭感觉。
> 证据分级：**[实测]** = 本机/手机真机测出来的数字；**[官方]** = 厂商页面/文档的公开说法（未实测）；
> **[未核实]** = 业内常见说法但没有可靠公开来源，只作参考。

## 一句话定位

我们是"**单台 Windows 主机 + 手机/浏览器，零安装、不经厂商云、高帧率低延迟**"；
大厂是"**全平台客户端 + 全球中继网络 + 企业级管理**"。
比极致延迟和高帧率我们不虚，比"跨网络随便连、什么设备都能装、企业要的管理功能"我们差得远。

## 我们**优于**大厂的地方

1. **零安装**：对方给个链接，浏览器/微信里点开就能看能控。大厂里只有 Parsec/Chrome Remote Desktop 有网页版，其余都要装客户端；国内产品装完还要登录、绑手机号。
2. **真高帧率**：我们 120fps 档实测"解码 121 / 画出 120"，240fps 档也能跑（离线与真机都有数据）。
   官方给到 240fps 的只有 Parsec；Moonlight 是 120fps；其余普遍 30~60fps。
3. **不经厂商云**：WebRTC 直连（Tailscale/局域网/热点），画面和输入不落第三方服务器。
   Parsec 也是 P2P，但它必须过它的账号与协调服务；国内产品默认走自家云中继。
4. **没有账号体系**：密钥 + 设备码即可，不存在"注册—登录—实名—云同步"这条链，也没有封号/风控风险。
5. **离线/局域网可用**：没有互联网、没有 Tailscale 也能连（热点/USB 共享/局域网 HTTPS），
   大厂离线场景基本都要"先登录一次"。
6. **免费无限制**（当前策略）：大厂免费档都有广告、时长、画质或设备数限制。
7. **可观测性**：我们内置 `/health`、`/h264-status`（关键帧体积、到达节奏、呈现分账）、页面 `[wc264-diag]`，
   还有 `qos-test.mjs`/`stress-test.mjs`/`pacertest.mjs` 三件套。大厂不会把这些交给用户。
8. **单文件部署、可控**：整条链（Node 服务 + ffmpeg + 侧车 + 输入注入 + 音频）都在本机，出问题能自己查。

## 我们**劣于**大厂的地方（按影响排序）

1. **跨网连接依赖外部条件**：我们靠 Tailscale（或端口转发）打洞，没有自己的全球中继网络。
   遇到"对称 NAT + 公司网络封 UDP"这类场景，大厂的 relay 能兜住，我们只能退回 WS/中继或直接连不上。
2. **客户端生态窄**：只有浏览器 + Android WebView/APK 壳；**没有 iOS/macOS/Linux 原生客户端**，
   也没有 Apple TV / 电视 / 游戏机端（Moonlight 几十种设备）。
   iOS 上 Safari 的 WebCodecs 支持不全，体验会退化成 <video> 路径（延迟更大）。
3. **只有 H.264**：没有 HEVC/AV1。同样画质下我们带宽更高（Parsec 4:4:4、Moonlight H.265/AV1+HDR 都更强）。
4. **画质特性缺失**：无 HDR、无 4:4:4、无 10bit；多显示器只能"切着看"，不能同时看多屏阵列。
5. **企业能力缺失**：无 SSO/SCIM、无审计日志、无权限分组、无批量部署（MSI）/无人值守策略（AnyDesk/Parsec Teams 有）。
6. **外设支持少**：有文件传输、剪贴板（部分）、单向音频；没有麦克风回传、打印机重定向、手写笔压感、手柄映射（Parsec Warp/Moonlight 有）。
7. **合规/安全背书**：大厂有 SOC2/ISO27001、第三方渗透测试；我们是自研自测（安全设计有：密钥、Tailscale ACL、无云中转，但没有外部认证）。
8. **签名与分发**：安装包没有 EV 代码签名/应用商店分发，Windows SmartScreen 会提示；大厂没有这个问题。
9. **移动端打磨**：手势、软键盘、外接键鼠映射、震动/姿态等，原生 app 普遍做得更细。
10. **支持体系**：无客服 SLA。大厂有工单/电话/知识库。

## 结论与建议（下一步最值得做的）

- **定位**：不要跟大厂比"全平台 + 企业中台"，我们赢在"零安装、不经云、高帧率、可自诊断"。
- **按投入产出排序的补强**：
  1. **HEVC 硬件编码**：带宽砍 30~50%（同样的 20Mbps 能换更清晰的 120fps），代价是兼容性要探测；
  2. **iOS/平板体验**：Safari 走 `<video>` 降级 + 手势，别让 iPhone 用户看到"能开但很卡"；
  3. **无 Tailscale 的兜底**：内置 TURN（已有一点点）/端口转发向导，覆盖"公司网封 UDP"；
  4. **多显示器同时看**：现在只能切，加到"两路同时编码"（已有 B2 双路基础）；
  5. **移动端输入打磨**：软键盘、触控板手势、手柄映射。
- **明确不做**：企业 SSO/审计/批量部署（那是另一个产品），全球中继网络（成本与合规都重）。
