# 机械码绑定 & 7 天试用防白嫖 · 审计（2026-11-02）

> 起因：用户问「机械码是不是绑死一台机器？对方能不能换系统白嫖 7 天体验？」
> 结论先行：**许可证绑死这台机器的 CPU + 主板，重装系统不影响、也不会失效；但 7 天试用只是本机记录，重装/重置系统（或清掉那几处记录）会重新发 7 天，而且可以反复。**
> 这是 `trial.ps1` 里写明的设计限制，不是新发现的 bug。

---

## 一、机械码是怎么算的

`app/licence.ps1` → `Get-LicenceMachineCode`：

```
原文 = CPU ProcessorId | 主板 SerialNumber | 主板 Product      （全小写）
机械码 = SHA256(原文).hex 取前 16 位 → 大写 → 每 4 位加连字符
```

刻意**不含**：硬盘序列号（换硬盘不该失效）、MachineGuid（重装系统就得重发许可证，售后受不了）。
拿不到 CPU/主板信息时才退回 MachineGuid。

本机实测（2026-11-02）：

| 项 | 值 |
|---|---|
| CPU ProcessorId | `178BFBFF00A60F12` |
| 主板序列号 | `PF5M15P1` |
| 主板型号 | `LNVNB161216` |
| 拼出来的原文 | `178bfbff00a60f12\|pf5m15p1\|lnvnb161216` |
| 机械码（与服务端/trial.json 一致） | `5FE5-CFE7-7B27-370B` |

所以：

- **换硬盘、重装 Windows** → 机械码不变 → 许可证照常有效。（产品的宣传口径"换硬盘/重装系统不受影响"成立。）
- **换 CPU 或换主板** → 机械码变 → 许可证失效，需要重发。（"绑死一台机器"的实际含义就是这个组合。）

## 二、7 天试用是"本机四处锚点"，不是服务端记录

`app/trial.ps1`：

- 首次安装时把「首装时间」写进 **4 个安装目录之外**的位置，之后每次取其中**最早**的一条当锚点：
  1. `HKLM\SOFTWARE\PhoneAccess`（TrialStart / TrialChk / TrialLastSeen）
  2. `HKCU\SOFTWARE\PhoneAccess`（同上）
  3. `%ProgramData%\PhoneAccess\trial.json`
  4. `%LOCALAPPDATA%\PhoneAccessTrial\trial.json`
  （安装目录里的 `trial.json` 是第 5 份副本，卸载会删掉，仅作兜底）
- 每条记录带 `machine`（机械码）+ `chk = SHA256(machine|start|salt)`，改时间不重算 chk 会失效。
- 带 `lastSeen`：系统时间往回调超过 1 天 → 判 `clock-tamper`，试用直接失效（**改系统时间这条路是堵死的**）。
- 本地记录被人为删光时：**无法与服务器对账**（产品没有中心服务器）。这一点写在同一文件的注释里。

本机实测四处都在（`2026-10-30 21:27:33` 起，lastSeen 一直在推进）。

## 三、能不能白嫖？——能，而且可以反复

| 手法 | 是否可行 | 说明 |
|---|---|---|
| 卸载重装 | ❌ 不行 | 锚点在安装目录之外，卸载脚本不删它们（这是当初的设计） |
| 改系统时间 | ❌ 不行 | lastSeen 回拨 >1 天判作弊 |
| **重装 / 重置 Windows** | ✅ **可以** | 四处锚点全被清掉，机械码不变，程序读不到锚点 → 当"首次安装"，**重新发 7 天** |
| **手动清掉 4 处记录** | ✅ 可以 | 需要管理员权限（安装器本来就要管理员）；清完再启动就是新的 7 天 |
| 装到另一台电脑 | ✅ 可以 | 机械码不同 → 也发新的 7 天（每台机器的"首装"都算） |
| 虚拟机快照回滚 | ✅ 可以 | 和重装同类：本地状态回滚 |

**白嫖到的价值有限**（这点很重要）：

- 试用解锁的是：超清 2560 不限时长 + 个性化（主题/光标/自定义）+ 同时观看不限台数。
- 免费版本身**永久可用**（画面/触控/声音/流畅/高清/标准都免费，超清每天 1 小时）。
- 所以白嫖收益 ≈ 专业版 ¥68 的增值部分，而且要每 7 天重装一次系统——对大多数人不划算；
  对少数技术人员则是"顺手就绕过了"。
- 付费客户不受影响：重装系统后许可证仍然有效（机械码没变）。

## 四、更值得注意的一个漏洞：同型号 DIY 台式机会撞码

- `Win32_Processor.ProcessorId` 是 CPUID 派生值，**同型号 CPU 完全相同**（不是每颗唯一）。
- 很多 DIY 主板的 `SerialNumber` 是 `To be filled by O.E.M.` / `Default string`，会被 `licence.ps1` 的过滤规则丢掉，
  最后机械码只剩「CPU ProcessorId + 主板型号」。
- 结果：**两台同 CPU、同主板型号的 DIY 台式机 = 同一个机械码**，一份许可证能装两台。
- 品牌机/笔记本不受影响（序列号真实，本机 `PF5M15P1` 有效）。

**低成本修法（可选）**：把 `Win32_ComputerSystemProduct.UUID`（SMBIOS UUID，同主板/重装系统都不变）
拼进机械码；遇到全 `0`/全 `F` 的占位值就忽略。
代价：**算法一改，所有已发的老许可证都会失效**（机械码变了）。必须双算法兼容：
先按新算法验，失败再按旧算法验一遍，两套都通过才算这台机器。这个改动适合放进下一次大版本。

## 五、要真堵住"重装系统刷新试用"，只有三条路

### 1) 服务端台账（唯一根治）

客户机首次运行时把机械码 POST 到一个很小的接口，服务端记录「这台机器第一次领试用的时间」；
之后不管怎么重装，返回的都是同一个起点。客户端取 `min(本地锚点, 服务端起点)`。

- 实现：腾讯云云函数 / 阿里云函数计算 + 云数据库（都有免费额度），或最便宜的轻量服务器（约 ¥2x/月）。
  一个接口 + 一张表就够：`POST /trial {machine}` → 返回 `{start}`；不存在就写入当前时间。
- **必须做失败降级**：连不上服务端时照常按本地锚点发试用，绝不能因为网络把客户锁死。
- 隐私口径：只上传机械码（哈希），不含任何客户信息；对外可以说清楚。

### 2) 人工发试用码

把「自动 7 天」改成「找卖家领 7 天体验码」。现有工具已经具备：`make-licence.ps1 -Days 7 -Edition trial`，
`seller-keys\` 里有台账，`tools\count-trial-licences.ps1` 能按机械码查已购次数。
防白嫖效果最好，但会损失一部分自动转化，也要人工响应（每单一次）。

### 3) 接受现状（成本最低）

口径写成「卸载重装不刷新；重装系统/清记录会重新计算」，对外**不要**宣称"绝对防破解"。
以 ¥68 买断 + 免费版永久可用的定位，实际损失有限；把精力放在功能和售后上更划算。

## 六、其它审计结论

- 许可证校验链没看到新漏洞：RSA-2048 验签 → 机械码比对 → 严格 `yyyy-MM-dd` 日期 →
  六个签名字段禁换行 → 机器码为空时 fail-closed（不跳过比对）。
- 「体验版每台最多 3 次」靠人工核对 `seller-keys\licence-*.json` 台账，不是强约束。
- 卸载脚本不碰试用锚点（符合"卸载重装不刷新"的设计）。
- `machine.id` 缓存启动时用 `-Force` 重算（第二轮审查 M1 的修复已生效），日常守护走缓存。

---

## 七、建议（给卖家的一句话）

先保持现状即可：**试用能重置，但只值 7 天超清+个性化，重装系统的代价比 ¥68 高**。
如果以后客户量大了、发现有人批量重置，再上「服务端台账」（§5.1），
顺便把「同型号 DIY 撞码」一起修掉（§4，双算法兼容）。
