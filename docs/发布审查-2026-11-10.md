## 二、审查发现与处置

### P0 侧车 exe 硬编码开发者身份（已修）

- 证据：包里 `rtc-h264\rtc-h264.exe` 中 `C:/Users/ccj/...` ×1170、`D:/download/办共/...` ×2
  （Go 的 pclntab 源码路径表；偏移 7946443 起可见 `D:/download/办共/phone-...`）。
- 根因：三段 scrub 只按扩展名白名单跑（`.ps1 .cmd .mjs .json .vbs .md .txt .cjs`），**从不处理 .exe**。
- 修法：`go build -trimpath -buildvcs=false` 重编（16,115,200 → 16,077,312 B），实测三类路径命中 0；
  把编译要求写进 `app\rtc-h264\main.go` 顶部注释；生产侧车同步换成这版（哈希与仓库一致）。

### P1 `capture.exe.bak` 混进客户包（已修）

- 证据：包根 18,432 B 的旧抓屏程序；`install.ps1` 的 `$requiredFiles` 与 Defender `$exclFiles` 都在引用它
  （只删文件不改 install.ps1 会让安装校验失败）。
- 修法三处同改：`app\pack.ps1`（复制清单 / 必需清单 / `*.bak` 白名单例外）、
  `app\install.ps1`（`$requiredFiles` / `$exclFiles`）。包文件数 329 → 328。

### P2 设备审查误判后画质不自动还原（已修）

- 场景：开机时锁屏/远程桌面 → 采集探针失败 → 判 fallback → 压到 1280×800@30/8Mbps；
  之后真实出帧会把**等级**修回 good，但**画质要重启才回来**（会误伤正常机器）。
- 修法：`deviceApplyCaps()` 把被压之前的原值记进 `DEVICE.clamped`；`h264MarkAvailable()` 自愈时
  **仅当"当前值仍等于我们强制的值"才还原**（不覆盖用户手调），`/device-check` 多返回 `clamped`。
- 端到端复验：隔离实例强制 fallback → 1280×800@30/8000 → 60 秒冷却重试出帧 →
  `[device] 实际出帧成功：设备等级从 fallback 修正为 good，画质已恢复为 1920x1200@90 50000kbps`。

## 五、本轮打包踩到的坑（写给下一次）

1. **Go 产物必须 `-trimpath`**，否则路径/用户名进 exe，而 scrub 管不到 .exe。
2. **`capture.exe.bak` 这类".bak 白名单例外"很容易漏**：删文件必须同时改 `install.ps1` 的必需清单，
   否则客户机上安装校验直接失败。
3. **SFX 尾部格式**是 `[magic][启动器大小][zip 长度]`，两个 u64 是**小端**；按"offset/length 大端"读会解不开。
4. 生产侧车的 `-40` 秒退、pixel 预算这些历史坑不再复述，见 `docs\交接-2026-11-10-花屏回归.md`。
