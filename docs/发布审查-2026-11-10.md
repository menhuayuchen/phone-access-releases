## 二、三轮审查发现与处置

### 第一轮：2 条阻塞

**P0 侧车 exe 硬编码开发者身份**（已修）
- 证据：包里 `rtc-h264\rtc-h264.exe` 中 `C:/Users/ccj/...` ×1170、`D:/download/办共/...` ×2（Go 的 pclntab 源码路径表）。
- 根因：三段 scrub 只按扩展名白名单跑（`.ps1 .cmd .mjs .json .vbs .md .txt .cjs`），**从不处理 .exe**。
- 修法：`go build -trimpath -buildvcs=false` 重编（16,115,200 → 16,077,312 B），三解码全 0；
  编译要求写进 `app\rtc-h264\main.go` 顶部注释；生产侧车同步换这版。

**P1 `capture.exe.bak` 混进客户包**（已修）
- 它是旧抓屏程序的 18KB 备份，`install.ps1` 的 `$requiredFiles` 与 Defender `$exclFiles` 都在引用它
  （只删文件不改 install.ps1 会让客户机上安装校验直接失败）。
- 修法三处同改：`app\pack.ps1`（复制清单 / 必需清单 / `*.bak` 白名单例外）、`app\install.ps1`（`$requiredFiles` / `$exclFiles`）。329 → 328 文件。

**P2 设备审查误判后画质不自动还原**（已修，见第二轮补充）
- 场景：开机锁屏/远程桌面 → 采集探针失败 → 判 fallback → 压到 1280×800@30/8Mbps；之后真实出帧只把**等级**修回，
  **画质要重启才回来**（误伤正常机器）。
- 修法：`deviceApplyCaps()` 记 `DEVICE.clamped`；`h264MarkAvailable()` 自愈时仅当"当前值仍等于我们强制的值"才还原，
  `/device-check` 多返回 `clamped`。

### 第二轮：P2 的修法本身有 bug（R3，已修）

- 独立审查员把包内真实字节切出来跑三场景，发现还原的**上界用错了**：用的是配置上限（240/100000），
  而不是自愈后的新设备上限。后果：没有硬件编码的机器自愈到 basic(30fps/12Mbps/1600)，
  却会被还原成 **90fps/50Mbps/1920~2560 宽去跑软件编码** —— 正是设备审查唯一要阻止的状态，而且不会自动纠正。
- 修法（3 行）：`const nc = DEVICE.caps;`，三处还原上界改成 `nc.maxFps / nc.maxKbps / nc.maxWidth`，宽度补 `evenDown()`。
- 复算结果：A 有 NVENC → 90/50000/1920（在限内）；B 无 NVENC → **30/12000/1600**；C 无 NVENC+2560 屏 → **30/12000/1600**。

## 五、遗留（非阻塞，下个版本处理）

1. **发布包 `product.config.json` 的 `experiments` 仍是 `{"enabled":true,"ocr":false}`**：
   虽然 `isSelfUse()` 对 release 返回 false、`/exp/*` 一律 404，但建议下版出包时把 release 包里的
   `experiments` 一并置空，免得读配置的人误判（防御性）。
2. **level 1（basic）没有自愈分支**：level 1 是"没有硬件编码"的稳定判定，不是瞬时误判，记录在案。
3. **`DEVICE.clamped` 在任一字段还原成功时就整体清空**：字段没还原的唯一原因就是"用户中途改过它"，
   此时本来就不该再还原，所以不算 bug；如果以后要更保守，可改成"只清已还原的字段"。
4. **自用轨管道名**：自用版 JS 里仍写 `dsh-*`，靠脚本显式传参覆盖成 `pa-*` 才没坏；发布版是自洽的那一侧。
   以后若简化掉传参，自用轨会先坏 —— 建议下版统一成 `pa-*`。
5. **`_说明` 类内部备注会随 `/licence` 下发到页面**（`support` 是整块透传的，所以 `support.bili._说明`
   那句构建备注也在 JSON 里）。不是秘密，但建议下版出包时剔掉 `_说明` 键，或让 `/licence` 只挑白名单字段。
   同理 `page.mjs` 里那处 `b23.tv` 注释也是包内仅存的提及（构建备注，无害）。

## 六、本轮打包踩到的坑（写给下一次）

1. **Go 产物必须 `-trimpath`**，否则路径/用户名进 exe，而 scrub 管不到 .exe。
2. **`.bak` 白名单例外很容易漏**：删包内文件必须同时改 `install.ps1` 的必需清单，否则安装校验失败。
3. **SFX 尾部格式**是 `[magic][启动器大小][zip 长度]`，两个 u64 是**小端**；按大端读会解不开。
4. 设备审查的采集探针**必须显式指定编码器**：`-f null` 不带 `-c:v` 时，这版 ffmpeg 裁掉了 `wrapped_avframe`，
   探针会永远失败，把所有客户都判成"采集不可用"。
