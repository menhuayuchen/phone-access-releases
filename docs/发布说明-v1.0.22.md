## 这次改了什么

### 一、画面更连贯（本轮最大的一块）

1. **关键帧突发治理（渐进式刷新）**
   以前每 0.5 秒一个"整帧关键帧"，1920x1200 下单个 310~490KB（平时一帧才 10KB），
   等于每半秒往链路上倒几千个包，弱网一抖就丢包重传、画面顿一下。
   现在改成"渐进式刷新 + 每 0.5 秒仍强制一个真关键帧"：
   - 关键帧体积 **310KB → 114KB**
   - 浏览器请求关键帧次数（PLI）**29 次 → 2 次**（2 分钟窗口）
   - 平均码率、帧率、关键帧间隔都不变

2. **修掉"解码 120 帧但只画出 95 帧"**
   根因在呈现调度器：它用"相邻帧到达间隔"估算内容帧率，而解码帧是成批到达的，
   结果 120fps 被估成 80fps → 每秒只画 80 帧，还把多出来的帧当积压丢掉。
   改成"按 1 秒窗口统计到达帧数"后：
   - 手机：画出 **95 → 118~120**（解码 120）
   - 本机浏览器（240Hz 屏）：画出 **77 → 120**
   - 30/60/240fps 档实测都能画满（100%）

3. **手机变暗/切后台不再把画面"重建"一遍**
   以前浏览器把刷新率压低时，页面会误判成"自己停摆了"，触发"重建接收端 + 自动降档"，
   用户回来发现画质被永久压低。现在区分三种情况：浏览器节流（只记日志）、断流（等帧）、
   真停摆（才自愈）。实测隐藏页面 3 分钟：0 次重建、0 次降档。

### 二、稳定性

- 稳定性压测 5 个场景（浸泡 / 接口轮询 / 反复切档 / 连接抖动 / 双路）：
  **事件循环卡顿 0 次、音频丢字节 0、写超时 0**，内存无泄漏。
- 编码器崩溃恢复：杀进程 3 次，**1.1 / 3.8 / 1.1 秒**恢复出图。
- 「两台设备各自画质」实验（C 方案）默认关闭，回到稳定的"共享主路"行为。
- 音频管道写超时 2 秒 → 5 秒，避免一次系统卡顿升级成断开重连丢音。
- 页面重载不再重启编码器；第二路空置 10 分钟自动回收。

### 三、新功能

- **息屏 v3**：真关背光（不是只盖黑），保持型（不跟着心跳掉），本机真人敲键盘/动鼠标才唤醒
  （远程注入的输入不算），最长 8 小时，服务重启后按状态继续。
- **未登录待机页**：开机没人登录时，手机打开也能看到"电脑已开机，请登录"。
- **Tailscale 诊断**：节点密钥到期提前提示；新增三件只读诊断（netcheck 体检 / 中继区域人话 /
  Funnel 公网暴露检测）。
- **页面热更新**：改页面不用重装 APK。
- **手机端**：呈现节奏跟随真实刷新率（屏幕给不到那么高时自动降一档）、帧率显示区分解码/呈现、
  全屏按钮常驻、长按恢复右键、"改地址"入口收进「更多」。
- **文件传输**：可显示并修改电脑端保存目录。
- 修掉「串流玩游戏」面板永远停在"正在检测…"的问题。

### 四、诊断（不影响使用）

- 新增 HEVC 能力探针（只上报，不改行为）。
- 诊断接口新增：关键帧体积统计、呈现循环分账（tick/未到点/空拍/抽帧/超限）、
  节流/隐藏标记 —— 以后查"卡一下"不用猜。

### 已知限制

- 240fps / 2560 宽度需要显卡与屏幕支持，启动时的"设备审查"会自动按机器能力封顶。
- 手机屏幕变暗时，浏览器会主动降低刷新率，画面会停住（这是浏览器行为）；
  现在的改进是它不会再引发"重建/降档"。
- HEVC（H.265）已完成评估与离线实测（等码率 +1.2dB，约省 20~30% 带宽），**本版未启用**，下一版再看。
