## 1. 侧车：H.265 打包 + SDP（验收通过）

### 关键发现（与交接文档不同，已实测确认）

交接文档说「Pion 没有 H265Payloader」，但 **pion/rtp v1.10.6（本仓库锁定版本）已经自带
`codecs.H265Payloader`**：单 NAL、AP 聚合、FU 分片、参数集缓存都有，且带完整单测。
所以不再自写一份 RFC 7798 打包器 —— 改用库里的实现，但**只用单 NAL + FU 两条路**
（`SkipAggregation: true`），与文档约定的方案完全一致（VPS/SPS/PPS 单独成包、IRAP 按 FU），
省掉一份自写打包器的风险。

### 改动

- 新增 `app/rtc-h264/h265.go`：`offerOpts`（codec + sprop/profile/level/tier）、`h265Fmtp()`、
  `newHEVCAPI()`（每次 HEVC offer 新建一份只注册 H265+Opus 的 MediaEngine，避免 m-line 里
  同时出现 H264 导致浏览器答 H264、侧车却推 H265 的错配）、输入清洗（非法 sprop 丢弃，防 SDP 注入）。
- `main.go`：`session` 增加 `codec` + `payloader rtp.Payloader`；`/offer` 读取 JSON body / `?codec=`；
  H264 会话继续用全局 api（默认 codec 表，行为不变）；HEVC 会话走 `newHEVCAPI`。
- `/health` 增加 `h264Sessions` / `hevcSessions`；版本 0.5.2 → **0.6.0**。
- 编译：`go build -trimpath -buildvcs=false`（沿用 1.0.22 的隐私要求）。

### 验收数据

1. **打包往返单测**（`go test -run 'H265|H264Path'`，`app/rtc-h264/h265_test.go`）：
   - 5 个 NAL（VPS/SPS/PPS/IRAP 4000B/非关键 600B）→ **8 个 RTP 包**；
     IRAP 切成 4 个 FU（S=1/E=1/mid=2），VPS 是首个完整单 NAL；无 AP（type 48）包。
   - 用 pion 的 `H265Depacketizer` 逐包还原：**4698 字节与输入逐字节一致**。
   - 3000B IRAP 分片后每包 ≤ MTU 1188；H264Payloader 单 NAL 行为未变（回归）。
2. **SDP（真实 /offer 返回，HEVC 模式）**：`m=video … 116`（**只有 H265**），
   `a=rtpmap:116 H265/90000`，
   `a=fmtp:116 level-id=153;profile-id=1;tier-flag=0;tx-mode=SRST;sprop-vps=…;sprop-sps=…;sprop-pps=…`。
   侧车日志核对 sprop 类型/长度：`vps=24B(type 32) sps=65B(type 33) pps=7B(type 34)`。
3. **原生 Chrome WebRTC H265 接收**（不经过我们页面/worker，验证打包本身）：
   1920×1200，**收 60.0fps / 解 60.0fps**（独立测试流 60fps），framesReceived=3722，
   framesDecoded=3722，**dropped=0**，PLI 全程 1 次；`host>host`。
4. **H.264 默认路径回归**（同一只新侧车、H264 会话）：WC264 解码 **121.2fps**，
   1920×1200，19.4Mbps，canvas 正常。

## 2. 服务端编码：hevc_nvenc + intra-refresh（验收通过）

### 实测 hevc_nvenc 能力（先测再改）

`D:\build\ffmpeg-hevc.exe -h encoder=hevc_nvenc`：

### 改动（`app/screen-server.mjs`）

- 新增 `screen.h264.codec`（`h264` 默认 / `hevc`），启动时探测 `hevc_nvenc`：

- `h264EncOnly()` 增加 HEVC 分支：`hevc_nvenc -preset p1 -tune ull -zerolatency 1 -rc cbr

- `/h264-status` 增加 `codec / codecDefault / hevcAvailable / hevcWhy / sampleEntry / codecString`。

## 3. 服务端解析：hvcC / IRAP / sprop（验收通过）

### 改动

- `h264ParseMoov`：兼容 `avc1` / `hvc1` / `hev1`，返回 `avcC` / `hvcC` / `sampleEntry`；
- 新增 `hevcHvcCInfo`（VPS/SPS/PPS 数组）、`hevcCodecString`（RFC 6381：`hvc1.<space><idc>.<compat>.<tier><level>[.<constraint>]`）；

## 4. 页面 / worker：HEVC 解码（验收通过）

### 改动

- `app/page.mjs`：
  - 新增 `resolveSessionCodec()`：`?codec=hevc|h264` 显式指定，否则跟 `/h264-status.codec`（配置默认）；
    上 HEVC 之前必须能力门禁 `rtp && wc && hw` 都为真（文档要求 wc&&hw，这里再加 rtp＝SDP 能谈 H265）。
  - codec 决策结果随 `/rtc264/offer?...&codec=` 发给服务端；以 **offer 响应的 codec** 为准
    （服务端在有其他观众/本机无 hevc_nvenc 时会降级），并把同样的值传给 worker。
  - HEVC 兜底：`hevcToH264()` —— 解码器报错立即触发；或 2.8 秒没解出画面触发。
    记 10 分钟"别再试"，回落期间**保留最后一帧**（不删画布），不黑屏。
- `app/wc264-worker.js`：
  - `codec` 消息决定按 H.264（1 字节 NAL 头）还是 H.265（2 字节、type=(b>>1)&0x3f）切 NAL；
  - HEVC 参数集 VPS(32)/SPS(33)/PPS(34) 从关键帧码流里取（服务端每关键帧前拼好）；
  - 现场组 `hvcC`（HEVCDecoderConfigurationRecord）当 `VideoDecoder` 的 description，
    codec 串按 RFC 6381 从 SPS 的 profile_tier_level 推（如 `hvc1.1.6.L153.90`）；
  - 关键帧 = NAL 16~21；参数集变化（编码器重启/切分辨率）重建解码器，与 H.264 同款防护；
  - 只支持 Main 8bit 4:2:0（服务端 `-profile:v main`），其它 profile 报错由页面回落。

## 6. 手机灰度第一次实测（2026-11-12 21:30，Android 16 / RMX8899 / Chrome 155 WebView）

- 手机确实发起了 HEVC：worker diag 里有 `codec hint -> hevc`，服务端日志 h264: start ... codec=hevc、
  init hvc1.1.6.L153.90，侧车也收到了 HEVC offer。
- 但 worker 侧 2.8 秒内 `rtp=0 / dec=0`，随后 `[rtc264-stop] 原因=retry:hevc->h264` ——
  **页面的兜底按设计生效，回落 H.264 后 125fps 正常出画**（用户截图里的「WebRTC264 直连」就是回落后的 H.264）。
- **根因不是 HEVC 解码失败**：offer 阶段服务端就把编码器切到 hevc 并拉起，但侧车 session 还在 pending（未 answer），
  `rtc264Status.sessions` 仍是 0；5 秒轮询 + 45 秒空闲判断把刚起的编码器停掉
  （日志：没有 WebRTC 会话也没有 WS 观众，停编码器），手机自然一帧都收不到。
- 修法（commit `9861f091`）：`onHealth264` 里 `pending>0` 时清空空闲计时并保活编码器；
  `offerSessionCodec` 里也立即清 `rtc264IdleSince`。本地复现：空闲 55 秒后发 HEVC offer 不 answer，
  9 秒后编码器仍在跑（codec=hevc / sampleEntry=hvc1 / framesIn=1122，修复前会在 5 秒内被杀）。
- 21:33 已把修复重新部署到生产并重启（配置仍是 `codec=hevc`），等手机**关掉页面重开**后复测。
  （回落会在 sessionStorage 记 10 分钟"不再试 HEVC"，下拉刷新清不掉，必须新开页面/新标签。）
