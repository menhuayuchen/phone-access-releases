# 服务端试用台账 · 部署与使用（2026-11-03，T1）

> 目的：堵住「重装系统 / 清掉本地记录 → 重新领 7 天试用」。
> 现状：7 天试用的起点只存在本机（注册表 + 两个目录，见 `docs/机械码与试用-审计-2026-11-02.md`），
> 重装系统会把这些全清掉，程序就把这台机器当"首次安装"，再发 7 天。
> 台账的做法：客户机第一次领试用时把**机械码**报给一个小接口，服务端记下"这台机器第一次领试用"的时间；
> 以后本地记录被清掉，客户机来问一次，拿回原来的起点 → 试用不会重新开始。
>
> 这一版是**可选功能**：`freemium.trialLedgerUrl` 留空 = 行为和以前完全一样，不联网。
> 服务端工具在 `tools/trial-ledger-server.mjs`（卖方侧，**不随产品发布**）。

---

## 一、客户端行为（`app/trial.ps1`）

| 场景 | 行为 |
|---|---|
| `trialLedgerUrl` 留空 | 完全按本地锚点，一次都不联网（现有客户无感） |
| 本地有锚点、也没有台账缓存 | **不联网**（正常机器永远不会请求） |
| 本地一个锚点都没有（重装/清记录） | POST 一次台账，拿回起点；比本地早（本地为空）就以台账为准 |
| 已有台账缓存（`trial-ledger.json`） | 7 天内直接用缓存，不联网；7 天后刷新一次 |
| 台账连不上 / 超时（4 秒） | 退回本地逻辑（**不锁死客户**），写 `failedAt`，6 小时内不再重试 |
| 台账返回的起点比本地晚 | 忽略，保持本地（不会"延长"试用） |
| 台账返回的起点比本地早 | 以台账为准（这台机器以前领过） |
| 地址不是 https | 直接拒绝，不发送（本机 `127.0.0.1`/`localhost` 放行，供自测） |

- 请求体：`{ "machine": "5FE5-CFE7-7B27-370B", "v": 1 }`（只上传机械码，机器码本身是 SHA256 哈希，不含任何客户信息）。
- 可选口令：`freemium.trialLedgerToken` 非空时带请求头 `x-ledger-token`。**它不是安全边界**（写在客户机配置里，能被扒出来），只防"被随手扫到"。
- 台账结果缓存在安装目录 `trial-ledger.json`（不含任何客户信息）。
- 只有 `licence-state.ps1` 被调用时才可能触发（它每 8 秒被守护进程跑一次，但**只有本地没锚点时才会真的联网**，所以日常没有额外开销）。

## 二、服务端：一条命令跑起来

```powershell
# 放在一台常开的机器/小服务器上（国内轻量服务器最省事）
<node.exe> tools\trial-ledger-server.mjs --port 18700 --data D:\pa-ledger\ledger.json --token 换成你的口令 --bind 127.0.0.1
```

- `--port` 端口（默认 18700）；`--data` 数据文件（JSON，自建）；`--token` 可选口令（给了就必须和客户端一致）；
  `--bind 127.0.0.1` 只给本机反代用，要直接对外就 `0.0.0.0`（但要自己做 HTTPS）。
- 接口：
  - `POST /trial` → `{ "ok": true, "start": "2026-11-03 18:36:22", "first": true|false }`
  - `GET /health` → `{ ok, machines, requests, at, token }`（自检用）
- 数据：`ledger.json` 里是 `{ machines: { "机械码": { start, seen, n } } }`。**定期备份这个文件**，
  删了就等于让所有机器重新领试用。

## 三、HTTPS（必须）

客户机只接受 `https://`。最简单的做法是套一层 Caddy（自动签证书）：

```caddyfile
pa-ledger.example.com {
    reverse_proxy 127.0.0.1:18700
}
```

然后客户端配置：

```json
"freemium": {
  "ultraFreeSecPerDay": 3600,
  "trialDays": 7,
  "freeMaxViewers": 3,
  "trialLedgerUrl": "https://pa-ledger.example.com/trial",
  "trialLedgerToken": "换成你的口令"
}
```

> 改 `product.config.json` 要**重新打包**才会到客户手上；留空时打包等于没启用，不需要改代码。

## 四、验证（本机就能做，不碰真实锚点）

```powershell
# 1) 起 mock 台账（本机回环放行 http，方便测试）
node tools\trial-ledger-server.mjs --port 18704 --data $env:TEMP\ledger.json --token sekret

# 2) 直接调用客户端函数
. app\trial.ps1
Get-LedgerStart -Url 'http://127.0.0.1:18704/trial' -Machine '5FE5-CFE7-7B27-370B' `
  -CachePath "$env:TEMP\lc.json" -Token 'sekret'
# → start 有值、$env:TEMP\lc.json 生成；再调一次应 cached=True（不联网）

# 3) 失败降级：停掉服务端再调一次 → 4 秒内返回空 start，缓存写 failedAt
```

2026-11-03 实测（13 项）：
- 带 token 查询成功、缓存命中不重复请求、新机器入库、401 不抛异常；
- 明文地址被拒绝且不发请求；
- `Merge-TrialAnchor` 四种组合（本地空/台账更早/本地更早/台账空）全部正确；
- 服务端挂掉时 4.03 秒返回并写 `failedAt`（6 小时内不重试）；
- 本机已有真实锚点时 `licence-state.ps1` **不联网**、起点不变（2026-10-30 21:27:33）。

## 五、边界（要对外说清楚）

- **不是绝对防破解**：客户如果断网 + 重装系统 + 清记录，台账问不到，仍然会拿到新的 7 天（这是"不能锁死客户"的代价）。
  台账能堵的是"联网状态下反复重装白嫖"，对普通用户已经够用。
- 台账**只记录、不验证**：它不签发许可证，也不影响付费客户的许可证校验。
- 换主板/换 CPU 后机械码会变（正常现象），台账会按新机械码当"新机器"——试用本来就绑机器，不冲突。
- 隐私口径：只上传机械码哈希；对外可以写明"试用需要联网核验一次首次领取时间"。

## 六、上线后怎么用

1. 在一台常开机器/小服务器上跑 `trial-ledger-server.mjs`，套 HTTPS。
2. `product.config.json` 填 `trialLedgerUrl`（+ 可选 token），重新打包发布。
3. 看 `GET /health` 的 `machines` 增长是否正常（只统计台数，不记录客户信息）。
4. 定期备份 `ledger.json`；不想启用就把 `trialLedgerUrl` 清空重新打包，客户端自动退回纯本地。
