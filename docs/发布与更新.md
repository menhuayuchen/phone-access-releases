# 发布新版与「检查更新」（GitHub Releases）

> 目标：客户在手机「设置 → 检查更新」里点一下，就能看到新版说明并一键下载安装。
> 不用发文件、不用教客户找网盘。本文是**卖家侧**操作手册。

## 〇、一条命令发版（推荐）

仓库里已经带了脚本，不用手工点 GitHub：

```powershell
# 1) 在 GitHub 建一枚 Personal Access Token（classic 勾 repo；fine-grained 给 Contents + Administration 写）
$env:GH_TOKEN = 'ghp_xxx'          # 只在当前窗口生效，别写进文件

# 2) 先预演（只校验 token / 仓库 / 版本，不真的上传）
.\tools\publish-release.ps1 -Owner 你的名字 -Repo phone-access-releases `
    -AssetPath 'dist\【点这里安装】手机远程-v1.0.7.exe' -DryRun

# 3) 正式发：会自动建仓库（不存在时）、建 tag v1.0.7、把 exe 传成 release asset
.\tools\publish-release.ps1 -Owner 你的名字 -Repo phone-access-releases `
    -AssetPath 'dist\【点这里安装】手机远程-v1.0.7.exe'
```

脚本会提醒你最后两步（填 `update.github`、重新打包）。下面的一、二节是手工流程，脚本出问题时按它排查。
## 一、一次性准备（只做一次）

1. 建一个 **public** 仓库，专门放安装包（不要放源码、不要放 `seller-keys`、不要放许可证）。
   建议名字：`phone-access-releases`。
2. 记下 `owner/repo`，例如 `ccj/phone-access-releases`。
3. 填进 `app/product.config.json`：

```json
"update": {
  "github": { "owner": "ccj", "repo": "phone-access-releases" },
  "url": "",
  "timeoutMs": 8000
}
```

> `url` 与 `github` 二选一，都留空 = 只显示当前版本、提示联系卖家。
> 这个配置会随包分发，改完要重新打包才会到客户机器上。

## 二、每发一版的流程

1. **改版本号**：`app/product.config.json` 的 `version`（例如 `1.0.6` → `1.0.7`）。
   这是「检查更新」比大小的唯一依据，**忘了改就永远提示已是最新**。
2. **打包**：`pack.ps1` → 生成 `dist\<时间戳>\`。
3. **做单文件安装包**：`sfx\build-sfx.ps1`（会自动重编 `Sfx.exe`，确保带上安装前声明弹窗）。
4. **建 release**：
   - Tag：`v1.0.7`（**必须带 v**，服务端会自动剥掉 `v` 再和 `1.0.7` 比）
   - 标题：`v1.0.7`
   - 说明：贴客户看得懂的话（这版改了什么）。这段正文会原样显示在客户手机上（超长会截断到 900 字）。
   - **不要勾 Pre-release**（`/releases/latest` 只认最新正式版）
5. **上传安装包**：把 `【点这里安装】手机远程-v1.0.7.exe` 拖进去当 asset。
   服务的挑选顺序：名字里带 `setup/install/安装/手机远程` 的 `.exe` → 任意 `.exe` → 退回 release 页面。
6. **自测**（重要）：找一台已装旧版的机器，点「检查更新」，确认：
   - 看得到新版本号与说明
   - 「下载并安装」按钮走完下载、安装程序能起来
   - 装完版本号变了、许可证还在

## 三、客户那端会发生什么

- 只有**客户主动点「检查更新」**才联网一次；产品平时不做出站请求、不轮询。
- 服务端读 `https://api.github.com/repos/<owner>/<repo>/releases/latest`，比较版本；
  有新版就显示说明 + 「下载并安装」。
- 点「下载并安装」后：服务端下载到 `%TEMP%\PhoneAccess-Update-*.exe` 再启动它。
  只允许 GitHub 的下载域名与 `.exe`，页面不能让它下载任意网址。
- 安装新版**不会动** `licence.json`、`product.config.json` 里的画质设置和试用锚点。

## 四、排错

| 现象 | 原因 / 处理 |
|---|---|
| 提示「还没配置更新源」 | `update.github` 两个字段没填，或没重新打包 |
| 提示 `GitHub 返回 404` | 仓库名写错 / 仓库是 private / 没有 release |
| 提示 `GitHub 返回 403` | 客户网络访问 GitHub 被限制（国内常见）。改用 `update.url` 指向自己的静态 JSON + 网盘直链 |
| 有新版但提示「已是最新」 | `version` 没改，或 tag 没带 `v`（`1.0.7` 会被拿去和 `1.0.6` 比，正常；但格式乱就比不对） |
| 显示新版但点不动 | release 里没有 `.exe` asset，页面只给发布页地址 |

## 五、备选：不用 GitHub 的私有更新源

国内客户访问 GitHub 经常不稳定。备选方案是任何返回 JSON 的地址：

```json
{ "version": "1.0.7", "notes": "这版修了什么", "url": "https://你的域名/PhoneAccess-Setup-1.0.7.exe" }
```

填进 `update.url` 即可。注意：`/update-install` 只允许 GitHub 的下载域名，
用私有源时客户页面只显示下载地址（手动点浏览器下载），不会自动下载安装——
这是故意的安全边界，别为了省事把任意域名开放给它。

## 六、费用与限制

- 公开仓库的 Release 免费，单个文件上限 2 GB，本产品安装包约 50 MB，完全够。
- 不要在 release 里放源码压缩包、许可证、私钥。

## 七、踩过的坑（2026-10-30 首发 v1.0.6 实录）

| 现象 | 真实原因 | 现在怎么处理 |
|---|---|---|
| 建 release 报 **403** | 细粒度 token 只有 `Contents: Read`，或仓库访问选了 "Public repositories（只读）" | GitHub → token 设置里：Repository access 选 **Only select repositories** 并勾上本仓库；Permissions 里 **Contents = Read and write** |
| 建 release 报 **404**（看起来像没权限） | 仓库是**空的**（没有任何 commit），GitHub 建不了 tag，用 404 冒充权限错误 | 脚本现在会自动提交一个 README 初始化仓库再重试 |
| 附件名变成 `-v1.0.6.exe` | GitHub 会把 asset 名里的**非 ASCII 字符**清洗掉 | 脚本自动改用 `PhoneAccess-Setup-vX.Y.Z.exe` 上传，本地文件仍可保留中文名 |
| 客户端点「检查更新」说"还没配置" | 打包时 `product.config.json` 的 `update.github` 还是空的 | 先填 `update.github`，**再打包**；脚本结束时会检查是否已指向本仓库 |

### 特别提醒：1.0.5 及更早的客户**不能**自动升级到 1.0.6

GitHub 更新是 1.0.6 才加进 `screen-server.mjs` 的功能，旧版客户端里根本没有这段代码。
所以这一次必须**手动把 1.0.6 安装包发给他们**；从 1.0.6 起，以后的新版本才能靠「检查更新」自动升级。
老客户保留配置和许可证，直接双击新安装包覆盖安装即可。
