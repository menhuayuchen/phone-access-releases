# 发布新版与「检查更新」（GitHub Releases）

> **发版铁律（2026-10-30 用户要求）**
> 1. **发布版本必须经过用户明确同意**：改 `version`、打包、上传 GitHub Releases、改 `latest`，四件事都算"发布"。
> 2. **不要频繁迭代版本**：零散改动先在仓库里改好、commit，攒成一批；不要每修一处就发一版。
> 3. 需要验证时可以**本地** `pack.ps1` + `build-sfx.ps1` 出候选安装包给用户装，但**不上传、不打 tag、不动 version**。
> 4. 用户说"可以发"之后，再按本文流程：bump 版本 → pack → build-sfx → publish-release（或 API）→ 更新落地页下载地址（用 /releases/latest 就不用改）。
> 5. **旧版本保留**（2026-11-02 用户要求）：已发布的旧版本不要从 GitHub / Gitee 删除，作为版本存档；
>    每个 Release 必须写清该版本改了什么。旧版在标题/说明里标「旧版归档」，`/releases/latest` 只指向最新正式版。
>    官网「更新记录」同步列出各版本改动与存档链接。

> 目标：客户在手机「设置 → 检查更新」里点一下，就能看到新版说明并一键下载安装。
> 不用发文件、不用教客户找网盘。本文是**卖家侧**操作手册。

## 〇、一条命令发版（推荐）

仓库里已经带了脚本，不用手工点 GitHub：

```powershell
# 1) 在 GitHub 建一枚 Personal Access Token（classic 勾 repo；fine-grained 给 Contents + Administration 写）
$env:GH_TOKEN = 'ghp_xxx'          # 只在当前窗口生效，别写进文件

# 2) 先预演（只校验 token / 仓库 / 版本，不真的上传）
.\tools\publish-release.ps1 -Owner 你的名字 -Repo phone-access-releases `
    -AssetPath 'dist\【点这里安装】手机远程-v1.0.7.exe' -DryRun

# 3) 正式发：会自动建仓库（不存在时）、建 tag v1.0.7、把 exe 传成 release asset
.\tools\publish-release.ps1 -Owner 你的名字 -Repo phone-access-releases `
    -AssetPath 'dist\【点这里安装】手机远程-v1.0.7.exe'
```

脚本会提醒你最后两步（填 `update.github`、重新打包）。下面的一、二节是手工流程，脚本出问题时按它排查。
## 一、一次性准备（只做一次）

1. 建一个 **public** 仓库，专门放安装包（不要放源码、不要放 `seller-keys`、不要放许可证）。
   建议名字：`phone-access-releases`。
2. 记下 `owner/repo`，例如 `ccj/phone-access-releases`。
3. 填进 `app/product.config.json`：

```json
"update": {
  "github": { "owner": "ccj", "repo": "phone-access-releases" },
  "url": "",
  "timeoutMs": 8000
}
```

> `url` 与 `github` 二选一，都留空 = 只显示当前版本、提示联系卖家。
> 这个配置会随包分发，改完要重新打包才会到客户机器上。

## 二、每发一版的流程

1. **改版本号**：`app/product.config.json` 的 `version`（例如 `1.0.6` → `1.0.7`）。
   这是「检查更新」比大小的唯一依据，**忘了改就永远提示已是最新**。
2. **打包**：`pack.ps1` → 生成 `dist\<时间戳>\`。
3. **做单文件安装包**：`sfx\build-sfx.ps1`（会自动重编 `Sfx.exe`，确保带上安装前声明弹窗）。
4. **建 release**：
   - Tag：`v1.0.7`（**必须带 v**，服务端会自动剥掉 `v` 再和 `1.0.7` 比）
   - 标题：`v1.0.7`
   - 说明：贴客户看得懂的话（这版改了什么）。这段正文会原样显示在客户手机上（超长会截断到 900 字）。
   - **不要勾 Pre-release**（`/releases/latest` 只认最新正式版）
5. **上传安装包**：把 `【点这里安装】手机远程-v1.0.7.exe` 拖进去当 asset。
   服务的挑选顺序：名字里带 `setup/install/安装/手机远程` 的 `.exe` → 任意 `.exe` → 退回 release 页面。
6. **自测**（重要）：找一台已装旧版的机器，点「检查更新」，确认：
   - 看得到新版本号与说明
   - 「下载并安装」按钮走完下载、安装程序能起来
   - 装完版本号变了、许可证还在

## 三、客户那端会发生什么

- 只有**客户主动点「检查更新」**才联网一次；产品平时不做出站请求、不轮询。
- 服务端读 `https://api.github.com/repos/<owner>/<repo>/releases/latest`，比较版本；
  有新版就显示说明 + 「下载并安装」。
- 点「下载并安装」后：服务端下载到 `%TEMP%\PhoneAccess-Update-*.exe` 再启动它。
  只允许 GitHub 的下载域名、配置里 `update.mirror` 的域名，以及 `.exe`；页面不能让它下载任意网址。
- **1.0.8 起下载过程可见**：页面每秒轮询 `/update-progress`，显示「已下载 x / 50.4 MB（xx%）·
  速度 · 预计还需 N 分钟」；连接 20 秒没响应、下载中 20 秒没新数据、平均速度低于 60KB/s 且还要
  超过 10 分钟、总时长超过 8 分钟——任一条件都会**立刻停止并给出原因**，不再无限「下载中…」。
- 安装新版**不会动** `licence.json`、`product.config.json` 里的画质设置和试用锚点。

## 四、排错

| 现象 | 原因 / 处理 |
|---|---|
| 提示「还没配置更新源」 | `update.github` 两个字段没填，或没重新打包 |
| 提示 `GitHub 返回 404` | 仓库名写错 / 仓库是 private / 没有 release |
| 提示 `GitHub 返回 403` | 客户网络访问 GitHub 被限制（国内常见）。配 `update.mirror` 指向国内直链 |
| 点「下载并安装」很久没反应 | 1.0.7 及更早要等 10 分钟才报错（国内实测 GitHub asset 只有 ~25KB/s）；1.0.8 起会在 20 秒~45 秒内明确报错。根治办法是配 `update.mirror` |
| 提示「连不上下载服务器」 | 客户到 GitHub 的 TCP 就不通（没开代理）。开代理重试，或让卖家发国内网盘链接 |
| 提示「下载太慢…已停止」 | 平均 <60KB/s 且预计还要 >10 分钟。配 `update.mirror` 国内直链 |
| 有新版但提示「已是最新」 | `version` 没改，或 tag 没带 `v`（`1.0.7` 会被拿去和 `1.0.6` 比，正常；但格式乱就比不对） |
| 显示新版但点不动 | release 里没有 `.exe` asset，页面只给发布页地址 |

## 五、国内下载：`update.mirror`（推荐）或私有 JSON 源

国内直连 GitHub 的 release asset 实测只有 ~25KB/s（52MB 要 35 分钟），基本不可用。
**最有效的办法**：把安装包同时放到一个国内能直连的 https 地址（阿里云 OSS / 腾讯云 COS 直链，
或你自己的静态站），然后：

```json
"update": {
  "github": { "owner": "menhuayuchen", "repo": "phone-access-releases" },
  "mirror": "https://你的桶.oss-cn-xxx.aliyuncs.com/PhoneAccess-Setup-v1.0.10.exe",
  "mirrorPage": "https://你的网盘分享页（可选）",
  "url": "",
  "timeoutMs": 8000
}
```

- 有 `mirror` 时：`/update-check` 把它作为首选下载地址、GitHub 作为备选；页面显示两个按钮
  「用国内镜像下载」/「改用 GitHub 下载」。`/update-install` 只额外放行这个 mirror 的域名。
  **（1.0.14 起主源改为 `update.gitee`，`mirror` 退化为老客户端兼容字段，见 §五点六）**
- 只接受 `https://...exe`；**换版本时记得同步改 mirror 里的文件名**，否则客户会下到旧包。
- **Gitee 也可以当 `mirror`**（2026-10-31 实测）：仓库建「发行版」上传 exe，链接形如
  `https://gitee.com/<owner>/<repo>/releases/download/<tag>/<file>`；无 cookie/Referer 可直连（302 到
  `foruda.gitee.com` CDN），实测 50 MB 下载约 35 秒（1.4 MB/s）。建议 tag/文件名用 ASCII（`v1.0.10`、
  `PhoneAccess-Setup-v1.0.10.exe`），中文虽然能用但 URL 会变成长串编码。
- `mirrorPage`：**没有稳定直链的网盘**（蓝奏云、123 云盘、夸克等）只能给一个"分享页"地址；
  下载失败时页面会多一个「国内网盘下载（手动）」链接，由客户自己在浏览器里下。
  蓝奏云的问题：下载页是 HTML+脚本，直链带防盗链、会变，**不能填进 `mirror`**（服务端没法直接下）。
  所以：自动更新要 OSS/COS 直链；蓝奏云只当手动兜底。
- 备选：`update.url` 指向任意返回 JSON 的地址
  （`{ "version": "1.0.10", "notes": "...", "url": "https://...exe" }`）。这种方式页面只显示下载地址，
  不会自动下载安装——安全边界，别为了省事把任意域名开放给 `/update-install`。

## 五点五、Gitee 国内镜像（推荐，已实测）

目的：让「检查更新 → 下载并安装」和官网下载走国内直链。实测 Gitee 发行版附件无 cookie/Referer 可直连，
50 MB 约 35 秒（1.4 MB/s），比 GitHub 的 ~25 KB/s 快约 50 倍。

### 一次性准备

1. 建仓库（公开）：`menhuayuchen/phone-access-download`（只放安装包，不放源码）。
2. 建私人令牌：<https://gitee.com/profile/personal_access_tokens> → 生成新令牌，
   权限勾 **projects**（仓库读写）+ **user_info**（校验账号）。
3. 双击 `tools\设置Gitee令牌.cmd`，粘贴令牌（不回显）→ 存到 `%USERPROFILE%\.gitee-token`。
   校验已保存的令牌：`powershell -File tools\set-gitee-token.ps1 -CheckOnly`

### 每发一版

1. 先把 `product.config.json` 的 `update.mirror` 写成**这一版**的 Gitee 直链：
   `https://gitee.com/menhuayuchen/phone-access-download/releases/download/v1.0.10/PhoneAccess-Setup-v1.0.10.exe`
   （tag 和文件名建议用 ASCII；中文能用但 URL 会变成长串 %E6… 编码）
2. 正常打包 → `dist\PhoneAccess-Setup-v1.0.10.exe`
3. 上传到 Gitee（一条命令）：

```powershell
& 'C:\Users\ccj\AppData\Local\PhoneAccess\runtime\node.exe' tools\publish-gitee-release.mjs `
  --owner menhuayuchen --repo phone-access-download `
  --tag v1.0.10 --name "手机远程 v1.0.10" --notes-file "$env:TEMP\release-notes.md" `
  --asset "dist\PhoneAccess-Setup-v1.0.10.exe" --verify
```

- 加 `--dry-run` 只校验令牌/仓库、打印计划，不创建/不上传；
- 脚本会自动建发行版、传附件，并（`--verify`）用不带 cookie 的请求验证下载地址；
- 令牌只从 `%USERPROFILE%\.gitee-token` 或环境变量 `GITEE_TOKEN` 读，**不会打印**。

### 注意（重要）

- `update.mirror` 读的是**客户端自己安装目录**里的 `product.config.json`：
  新客户端装「带 mirror 的版本」才自动走 Gitee；老客户端要手动改配置或重装才会变。
- 所以 mirror 必须和每个版本绑定（文件名带版本号），**改 mirror 要跟着发版一起做**，不能只改仓库不打包。
- Gitee 的免费发行版附件有单文件大小限制（50 MB 量级没问题；具体以页面提示为准）。
- 缓存/CDN：下载会 302 到 `foruda.gitee.com`，属正常；更换文件要换版本号，别覆盖同名附件。

## 五点六、更新源：Gitee 优先、GitHub 备选（1.0.14 起，2026-11-02）

客户大多在国内，`api.github.com` 慢或不通，所以 1.0.14 起 `/update-check` **默认走 Gitee**：

```json
"update": {
  "gitee":  { "owner": "menhuayuchen", "repo": "phone-access-download" },
  "github": { "owner": "menhuayuchen", "repo": "phone-access-releases" },
  "mirrorPage": "https://wwatu.lanzouv.com/iC6Kk4ef83bg",
  "mirrorPageNote": "密码 d0o2",
  "timeoutMs": 8000
}
```

行为：

1. 先拉 `https://gitee.com/api/v5/repos/<owner>/<repo>/releases?per_page=100`，
   在 tag 形如 `vX.Y.Z` 的产品发行版里挑**版本号最大**的那个（自动排除 `tailscale-android-*` 这类镜像 tag），
   把它的 `.exe` 附件直链作为默认下载地址。页面主按钮显示「国内下载（Gitee）」。
2. GitHub 只做备选：页面第二个按钮「改用 GitHub 下载」，地址按 release 约定拼
   `https://github.com/<owner>/<repo>/releases/download/v<版本>/PhoneAccess-Setup-v<版本>.exe`
   （不额外请求 GitHub API，省 8 秒超时）。
3. 只有 Gitee 拉不到版本时，才回退去问 GitHub API。
4. `update.mirror`（老字段）只在"它的版本号恰好等于最新版"时才用；老客户机器里的 mirror 永远指向老版本，
   所以**不会再被它顶掉 Gitee**（这是 1.0.13 及之前国内客户被迫走 GitHub 的根因）。
5. 下载后校验：Gitee 发行版**正文里写了 `SHA256：<64 位十六进制>`** 就会被当校验值
   （发版约定，必须写；`/update-install` 下完会核对，不一致就不运行安装程序）。
6. `mirrorPage` + `mirrorPageNote`：设置面板「安装备选」**常驻**显示（不点检查更新也能看到），
   蓝奏云这类没有稳定直链的网盘只放这里，不要填 `mirror`。
7. 发版顺序：Gitee 上传 → GitHub 上传 → 改官网 → 本机自测 `/update-check` 的 `source` 应为 `gitee`。

> 注意：Gitee 的 `/releases/latest` **不能用**——它返回"最近创建/修改的发行版"，
> 补传旧版归档后 latest 会指向旧版。必须像上面那样自己从列表里挑最高版本。

## 六、费用与限制

- 公开仓库的 Release 免费，单个文件上限 2 GB，本产品安装包约 50 MB，完全够。
- 不要在 release 里放源码压缩包、许可证、私钥。

## 七、踩过的坑（2026-10-30 首发 v1.0.6 实录）

| 现象 | 真实原因 | 现在怎么处理 |
|---|---|---|
| 建 release 报 **403** | 细粒度 token 只有 `Contents: Read`，或仓库访问选了 "Public repositories（只读）" | GitHub → token 设置里：Repository access 选 **Only select repositories** 并勾上本仓库；Permissions 里 **Contents = Read and write** |
| 建 release 报 **404**（看起来像没权限） | 仓库是**空的**（没有任何 commit），GitHub 建不了 tag，用 404 冒充权限错误 | 脚本现在会自动提交一个 README 初始化仓库再重试 |
| 附件名变成 `-v1.0.6.exe` | GitHub 会把 asset 名里的**非 ASCII 字符**清洗掉 | 脚本自动改用 `PhoneAccess-Setup-vX.Y.Z.exe` 上传，本地文件仍可保留中文名 |
| 客户端点「检查更新」说"还没配置" | 打包时 `product.config.json` 的 `update.github` 还是空的 | 先填 `update.github`，**再打包**；脚本结束时会检查是否已指向本仓库 |

### 特别提醒：1.0.5 及更早的客户**不能**自动升级到 1.0.6

GitHub 更新是 1.0.6 才加进 `screen-server.mjs` 的功能，旧版客户端里根本没有这段代码。
所以这一次必须**手动把 1.0.6 安装包发给他们**；从 1.0.6 起，以后的新版本才能靠「检查更新」自动升级。
老客户保留配置和许可证，直接双击新安装包覆盖安装即可。
