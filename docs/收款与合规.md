# 收款方式与合规（卖家侧备忘）

> 结论先说：**个人微信/支付宝收款码可以用，但别长期当主业收款渠道。**
> 它是"起步阶段能用、规模一上来就会卡"的方案。本文写清楚风险点和渐进升级路线，
> 目的是让你现在能用、将来不被冻号。

## 一、现在这套（产品里贴个人收款码）到底安全吗

| 风险 | 说明 | 严重度 |
|---|---|---|
| 平台风控 | 央行规定个人静态码不得用于**经营性**收款。频繁异地扫码、单笔偏大（几千元）、一天多笔，容易触发"限制收款/冻结" | **高** |
| 恶意举报 | 收款码随产品分发给客户，等于公开了你的收款入口。有人举报"诈骗"，微信/支付宝会先冻结再说 | 中高 |
| 账号混用 | 生活号兼收款，一旦被限制，连日常支付都受影响 | 中高 |
| 无凭证 | 没有订单号、没有平台担保，退款纠纷只能靠聊天记录 | 中 |
| 无法开票 | 客户要发票（尤其定制版/公司客户）直接卡住 | 中 |
| 税务 | 收入应申报，个人码流水长期不走账，迟早要解释 | 中 |

**产品侧还有一个小问题**：`branding\微信.jpg` / `支付宝.jpg` 是明文图片，任何拿到安装包的人
都能提取出来当"作者收款码"使用（冒充你收钱）。

## 二、立刻能做的四件事（不改代码）

1. **单独开一个收款账号**：别用生活号。微信/支付宝各开一个小号，只收货款，钱到账立刻转出。
2. **收款码加水印**：在图片上压一行字"仅用于手机远程许可证，其他用途无效"，
   并在码下面加你的联系方式。降低被拿去他处冒充的概率。
3. **每笔都要备注机器码后 4 位**，并让客户截图发你；你按"机器码 + 日期"建一个简单台账
   （Excel 就行），将来对账、处理退款、解释流水都靠它。
4. **写死退款规则**并挂在商品页：例如"许可证为虚拟商品，签发后 24 小时内可退，超过不退"。
   有规则，纠纷就有依据。

## 三、规模上来后的升级路线（按性价比排序）

| 方案 | 门槛 | 好处 | 代价 |
|---|---|---|---|
| **微信/支付宝 商户码（小微商户）** | 个人可申请（部分需营业执照） | 平台合规、有订单号、支持退款、可开发票 | 约 0.6% 手续费 |
| **虚拟商品平台**（如面包多/爱发电/微店） | 注册即可 | 自动发货、有担保、不用自己贴码 | 抽成 1%~5%，客户多一步跳转 |
| **个体户 + 对公账户** | 办个体户执照 | 正规、能开票、定制版大额可走对公 | 记账报税成本 |

**定制版（面议那一档）建议不要用个人码**：金额大、交付周期长，最好签个简单合同 + 对公/平台担保。

## 四、和产品功能的配合

- 专业版目前是**人工签发**（客户发机器码 → 你签 licence.json → 客户粘贴）。
  这条链路天然有聊天记录可查，比"自动发卡"更抗纠纷，起步阶段反而省事。
- 将来自动化时，把"支付回调 → 签发"接到商户号或平台 API，避免手工核对。
- 收款码图片目录：`app\branding\`（`微信.jpg` / `支付宝.jpg` / `联系.txt`），
  改完重新打包才会到客户端；已装客户可以只替换安装目录里的同名文件，不用重装。
